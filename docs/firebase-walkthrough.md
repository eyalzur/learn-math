# מדריך הקמה צעד-אחר-צעד: Firebase ל"לומדים חשבון"

המדריך הזה מבוסס על `FIREBASE_SETUP.md` ועל `api/README.md`. כל מה שמופיע כאן כשם תפריט או כפתור הועתק מהמסמכים האלה. מה שלא אומת במסמכים מסומן **"לאמת במסך"**.

**פרויקט Google Cloud:** `learn-math-506923`
**זמן משוער:** 15–20 דקות, בלי לחשב את זמן ההמתנה לפריסה.

---

## לפני שמתחילים

**חשוב:** אין צורך בחשבונות או בהגדרות כדי לראות את האפליקציה. המצב הדגמה (`VITE_CLOUD=mock`) עובד בלי כלום. ההגדרה הזו נדרשת רק כדי שהאפליקציה של ההורים והילדים תתחבר לשרת אמיתי.

**מה נשלח לעוזר בכל נקודת בדיקה (Checkpoint):**
- מותר לשלוח: שם הפרויקט, האם מתג מסוים דולק או כבוי, שם של סוד או משתנה (בלי הערך שלו), כתובת השרת (`https://…run.app`), וה-`firebaseConfig` (ציבורי, לא סוד).
- **אסור לשלוח לעוזר:** את הערך של `CHILD_TOKEN_SECRET`, קובץ מפתח של חשבון שירות, או סיסמאות. את הסוד יוצרים ומדביקים **רק** בשדה של GitHub Secrets בעצמכם.
- אם הופיעה שגיאה, שלחו את השורה המדויקת שלה. לא צריך צילום מסך של כל המסך.

**מי צריך את חשבון הבעלים:**
- שלבים 0, 1, 2 — חשבון הבעלים של הפרויקט ב-Google Cloud וב-Firebase (זה מי שיצר את הפרויקט).
- שלב 3 — חשבון שיש לו הרשאת מנהל (Admin) במאגר GitHub.
- שלב 4 — הרשאת כתיבה למאגר (Actions ו-Variables).
- שלב 5 — כל אחד עם טלפון, אבל ההורה הוא זה שמתקין.

## שלב 0 — מיזוג ה-PR (צריך אישור מפורש)

**מה לעשות:** לוודא שה-PR של הענף `feature/parent-subscription` כבר מוזג ל-`main`. ה-workflows של ה-API חייבים להיות ב-`main` כדי שיופיעו ב-GitHub Actions.

**איפה:** GitHub → המאגר → לשונית **Pull requests** → חפשו את `feature/parent-subscription`.

**בדיקה:** בלשונית **Actions** אמורים להופיע הפריטים **"Deploy parents-and-kids API to Cloud Run"** ו-**"Deploy to GitHub Pages"** בתוך רשימת ה-workflows בצד שמאל.

**אם ה-PR עוד לא מוזג:** לא ממזגים בלי אישור מפורש של בעל הפרויקט. זה כלל בפרויקט. רק אחרי האישור ממזגים (דרך ה-skill `merge-pr`).

**מה לשלוח לעוזר:** "מוזג" או "עוד לא מוזג".

**הערה:** האתר החי (`/learn-math/`) לא משתנה בשום שלב. המיזוג לא משפיע עליו, כי הבנייה של `/next/` מדלגת עד שמוגדר `NEXT_API_URL`.

## שלב 1 — Google Cloud, ב-Cloud Shell (פעם אחת, חשבון בעלים)

**1.1 פתיחת Cloud Shell**
1. פתחו את הקישור: https://shell.cloud.google.com
2. התחברו עם חשבון הבעלים.
3. אם מופיע חלון "Authorize" (אישור), לחצו **Authorize**. **לאמת במסך.**

**בדיקה:** מופיעה שורת פקודה שמתחילה ב-`@cloudshell` (לדוגמה `username@cloudshell:~ $`).

**1.2 הרצת הפקודות**
העתיקו את הבלוק הבא כולו, הדביקו אותו ב-Cloud Shell ולחצו Enter. השורות שמתחילות ב-`\` הן המשך של אותה פקודה. לא צריך לשנות דבר.

```bash
gcloud config set project learn-math-506923
gcloud services enable firestore.googleapis.com run.googleapis.com
gcloud firestore databases create --location=me-west1
gcloud iam service-accounts create learn-math-api --display-name="learn-math api"
gcloud projects add-iam-policy-binding learn-math-506923 \
  --member="serviceAccount:learn-math-api@learn-math-506923.iam.gserviceaccount.com" \
  --role="roles/datastore.user"
gcloud iam service-accounts add-iam-policy-binding \
  learn-math-api@learn-math-506923.iam.gserviceaccount.com \
  --member="serviceAccount:github-deployer@learn-math-506923.iam.gserviceaccount.com" \
  --role="roles/iam.serviceAccountUser"
```

**בדיקה:** כל פקודה מסתיימת בלי שגיאה. הודעה כמו `already exists` **אינה שגיאה**, וגם לא מפסיקה את ההגדרה. לא להתעכב עליה.

**מקרים מיוחדים:**
- אם כבר קיים מסד Firestore בפרויקט, השמיטו את השורה `gcloud firestore databases create ...` (שורה 3) והמשיכו.
- אם הפקודה `gcloud firestore databases create` מבקשת לבחור מצב (Native / Datastore), בחרו **Native mode**. **לאמת במסך.**
- אם מופיעה שגיאה בנוגע ל-`github-deployer` (לא נמצא), זה אומר שחשבון השירות הזה עדיין לא קיים בפרויקט. עצרו, שלחו את השגיאה לעוזר, ואל תנסו לתקן לבד. **לאמת במסך.**

**מה לשלוח לעוזר:** "שלב 1 עבר" + שם הפרויקט בפקודה הראשונה, או השגיאה המדויקת אם הייתה.

**דורש בעלים:** כן.

## שלב 2 — Firebase Console (חשבון בעלים)

**פתיחה:** https://console.firebase.google.com ← בחרו את הפרויקט `learn-math-506923`.

**בדיקה:** בראש המסך מופיע שם הפרויקט `learn-math-506923`. אם לא, בחרו אותו מהרשימה למעלה.

### 2a. שיטות כניסה (Sign-in methods)

1. בתפריט הצד: **Build** → **Authentication** → **Get started** (אם הכפתור מופיע. אם לא, דלגו לשלב 2).
2. בלשונית **Sign-in method**:
   - לחצו על **Google** ← **Enable** (הפעלה). בשדה **Project support email** בחרו את הכתובת שלכם. לחצו **Save**.
   - לחצו על **Email/Password** ← הפעילו את המתג הראשון (Enable). **בתוך אותה הגדרה**, הפעילו את המתג **Email link (passwordless sign-in)**. לחצו **Save**.

**בדיקה:** ליד **Google** מופיע הסטטוס **Enabled**. ליד **Email/Password** מופיע **Enabled**, ובתוכו המתג של **Email link** דולק.

**מה לשלוח לעוזר:** "Google: דולק" ו"Email link: דולק", או מה שמצאתם אחרת.

### 2b. דומיינים מורשים (Authorized domains)

1. בתפריט: **Authentication** ← לשונית **Settings** ← **Authorized domains**.
2. לחצו **Add domain** והקלידו: `eyalzur.github.io` (בלי `https://` ובלי `/` בסוף). לחצו **Add**.

**בדיקה:** ברשימה מופיעים: `localhost`, `learn-math-506923.firebaseapp.com`, ו-`eyalzur.github.io`. (`localhost` כבר שם מלכתחילה.)

**מה לשלוח לעוזר:** "eyalzur.github.io ברשימה: כן".

**אם הכפתור "Add domain" לא נראה:** לאמת במסך. בדקו שאתם בלשונית Settings ולא Sign-in method.

### 2c. הגדרת אפליקציית Web וקבלת ה-firebaseConfig

1. לחצו על גלגל ההגדרות (⚙) ליד **Project Overview** בתפריט הצד ← **Project settings**.
2. בלשונית **General** גללו ל-**Your apps**.
3. **אם כבר יש אפליקציית Web** (מופיע אייקון `</>` עם שם): לחצו על **Config** או על סמל ההגדרות שליד האפליקציה. **לאמת במסך.**
4. **אם אין אפליקציית Web:**
   - לחצו **Add app** ← בחרו את האייקון **Web** (`</>`).
   - בשדה השם הקלידו: `learn-math-web`.
   - **אל** תסמנו Firebase Hosting. לחצו **Register app**.
   - לחצו **Continue to console** (אם מופיע). **לאמת במסך.**
5. תחת **SDK setup and configuration** בחרו באפשרות **Config** (לא npm). יופיע האובייקט `firebaseConfig`.
6. העתיקו את האובייקט. הוא נראה כך:
   ```json
   {"apiKey":"…","authDomain":"learn-math-506923.firebaseapp.com","projectId":"learn-math-506923","appId":"…"}
   ```
7. הדביקו את התוכן בשורה אחת. ערך זה **ציבורי, לא סוד**, ומותר לשלוח אותו לעוזר.

**בדיקה:** ה-JSON מכיל את השדות `apiKey`, `authDomain`, `projectId`, `appId`, וה-`projectId` הוא `learn-math-506923`.

**מה לשלוח לעוזר:** ה-JSON המלא (שורה אחת). **זה המקום היחיד שבו מותר לשלוח את ה-JSON הזה.**

**דורש בעלים:** כן, שלבים 2a–2c.

## שלב 3 — סוד ב-GitHub (`CHILD_TOKEN_SECRET`)

**מה זה:** מחרוזת אקראית ארוכה שחותמת את החיבור של מכשירי הילדים. **לא מראים אותה לעוזר ולא שולחים אותה בצ'אט.**

### 3a. יצירת המחרוזת (במחשב שלכם, בטרמינל)
1. פתחו את **Terminal** במחשב (Spotlight ← הקלידו `Terminal`).
2. הקלידו את הפקודה הבאה ולחצו Enter:
   ```bash
   openssl rand -hex 32
   ```
3. יופיעה שורה של 64 תווים (אותיות לטיניות ומספרים). **העתיקו אותה.** אל תשמרו אותה בקובץ, אל תדביקו אותה בצ'אט.

### 3b. שמירה ב-GitHub
1. פתחו את המאגר ב-GitHub.
2. **Settings** (בשורת הלשוניות של המאגר, לא של החשבון) ← בתפריט הצד: **Secrets and variables** ← **Actions**.
3. לשונית **Secrets** ← לחצו **New repository secret**.
4. בשדה **Name** הקלידו: `CHILD_TOKEN_SECRET`
5. בשדה **Secret** הדביקו את המחרוזת מסעיף 3a.
6. לחצו **Add secret**.

**בדיקה:** ברשימת הסודות מופיע השם `CHILD_TOKEN_SECRET`, והערך מוסתר (כוכביות). אין אפשרות לראות את הערך שוב, וזה תקין.

**מה לשלוח לעוזר:** "CHILD_TOKEN_SECRET נשמר: כן". **שם בלבד.** לא את הערך.

**הערה חשובה:** אם תשנו את הסוד מאוחר יותר, כל מכשירי הילדים ייצאו מהחשבון, וכל ילד יצטרך להתחבר מחדש עם קוד חדש. זו התנהגות צפויה. לכן כדאי לשמור על אותו סוד.

**דורש בעלים/מנהל:** הרשאת Admin במאגר.

## שלב 4 — פריסה: API, משתנים, ואפליקציות

### 4a. פריסת ה-API ל-Cloud Run

1. ב-GitHub: לשונית **Actions** ← בצד שמאל לחצו על **Deploy parents-and-kids API to Cloud Run**.
2. לחצו **Run workflow** ← וודאו שהענף הוא `main` ← לחצו **Run workflow** (הכפתור הירוק).
3. המתינו עד שהריצה מסתיימת. זה לוקח כמה דקות.
4. **הריצה הראשונה עשויה להסתיים בירוק עם ההודעה "not deployed".** זה תקין כשהגדרות שלב 1–3 עדיין לא הושלמו. אחרי שסיימתם את השלבים, הריצו שוב.
5. כשהריצה נגמרת בהצלחה, פתחו אותה ובסיכום (Summary) מצאו את **כתובת השירות** שמתחילה ב-`https://` ומסתיימת ב-`.run.app`. העתיקו אותה.

**בדיקה:** הריצה ירוקה, וכתובת `https://…run.app` מופיעה בסיכום. **לאמת במסך** את המיקום המדויק של הכתובת.

**מה לשלוח לעוזר:** הכתובת המלאה (לא סוד) + "ירוק" או מה שכתוב בסיכום.

**אם הריצה נכשלת (אדומה):** ראו את טבלת הבעיות בסוף המדריך. שלחו לעוזר את השורה האדומה הראשונה מהלוג.

### 4b. משתני Variables

**חשוב:** אלה **Variables** ולא **Secrets**. בדקו את הלשונית הנכונה.

1. GitHub ← **Settings** ← **Secrets and variables** ← **Actions**.
2. לשונית **Variables** (לא Secrets).
3. לחצו **New repository variable** והוסיפו שניים:

| שם (Name) | ערך (Value) |
|---|---|
| `NEXT_API_URL` | כתובת השירות מ-4a, **בלי** `/` בסוף |
| `NEXT_FIREBASE_CONFIG` | ה-`firebaseConfig` מ-2c, בשורה אחת |

4. לחצו **Add variable** אחרי כל אחד.

**בדיקה:** ברשימת המשתנים מופיעים שני השמות. הערכים גלויים (בניגוד לסודות).

**מה לשלוח לעוזר:** "שני המשתנים נשמרו" + הערך של `NEXT_API_URL` (לא סוד).

### 4c. בניית Pages

1. GitHub ← **Actions** ← **Deploy to GitHub Pages** ← **Run workflow** ← וודאו שהענף `main` ← **Run workflow**.
2. המתינו לסיום. הריצה תבנה את `/next/`.

**בדיקה:** הריצה ירוקה. אחרי כמה דקות אפשר לפתוח:
- ילדים: https://eyalzur.github.io/learn-math/next/
- הורים: https://eyalzur.github.io/learn-math/next/parents/

**חשוב:** אם הגדרתם את המשתנים **אחרי** שהבנייה רצה, הבנייה צריכה לרוץ שוב כדי שהערכים ייכנסו לאתר. הריצו את 4c שוב.

**מה לשלוח לעוזר:** "Pages ירוק" + מה נפתח בקישורים.

**דורש בעלים/מנהל:** כן, הרצת workflows.

## שלב 5 — התקנה על הטלפון

**ההורה מתקין על הטלפון שלו.** הילדים נכנסים דרך אותו ההורה או דרך הקוד שמופיע אצל ההורה.

- **אייפון (Safari):** פתחו את הקישור ב-Safari ← כפתור **שיתוף** (ריבוע עם חץ למעלה) ← **הוספה למסך הבית** (Add to Home Screen).
- **אנדרואיד (Chrome):** פתחו את הקישור ב-Chrome ← תפריט (⋮) ← **התקנת אפליקציה** (Install app), או **הוספה למסך הבית**.

**בדיקה:** מופיע אייקון חדש במסך הבית, והאפליקציה נפתחת בלי שורת הדפדפן.

**מה לשלוח לעוזר:** "מותקן על אייפון/אנדרואיד" (לכל מכשיר).

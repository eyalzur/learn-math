# כותרות שנשברות בצורה מאוזנת — Architecture

## Overview
כלל CSS אחד, `text-wrap: balance`, נוסף לסלקטור ה-`h1` הגלובלי הקיים
ב-`src/index.css`. זו תכונת דפדפן מובנית שמחשבת שבירת שורות מאוזנת אוטומטית —
אין מנגנון חדש לכתוב, רק תכונת CSS קיימת שהדפדפן כבר יודע ליישם.

## Affected Files / Components
| קובץ | מה משתנה |
|---|---|
| `src/index.css` | שורה אחת נוספת בכלל `h1` (קווים 75-83 כרגע): `text-wrap: balance;`. שום שינוי אחר בקובץ — לא ל-`h2`, לא לשום כלל אחר. |

לא נוגעים בשום קובץ `.tsx` — הכותרות עצמן (`GradePicker.tsx`, `TopicPicker.tsx`
וכו׳) לא משתנות, כי הפתרון הוא ברמת ה-CSS הגלובלי שכולן כבר יורשות ממנו.

## Data / State Changes
None — CSS בלבד, שום state/props/טיפוס.

## Technical Approach
`text-wrap: balance` אומר לדפדפן לחשב את נקודת השבירה כך שהשורות יהיו קרובות
באורכן זו לזו, במקום למלא כל שורה עד שהמילה הבאה כבר לא נכנסת (ברירת המחדל,
`text-wrap: wrap`). זו התנהגות דפדפן טבעית — לא JavaScript, לא מדידה ידנית של
רוחב טקסט.

נוסף רק לסלקטור `h1` הקיים (לא ל-`h1, h2` המשותף שכבר קיים בקובץ, כי הכלל של
`font-family`/`color` שם משותף אבל השבירה המאוזנת ספציפית ל-`h1` לפי product-spec).

## Edge Cases
- **דפדפן ללא תמיכה:** `text-wrap: balance` הוא שיפור מתקדם (progressive
  enhancement) — דפדפן שלא מכיר את הערך פשוט מתעלם ממנו וממשיך להתנהג כמו היום
  (`text-wrap: wrap` המשתמע). אין נסיגה חזותית, רק היעדר השיפור. תואם את
  ה-Out of Scope ב-product-spec ("אין תמיכה בדפדפנים ישנים" — כי אין צורך
  בתמיכה מיוחדת, רק חוסר-נזק).
- **כותרת בשורה אחת:** `text-wrap: balance` לא משפיע כשאין שבירה בכלל — הדרישה
  ב-product-spec ("כותרת שנכנסת בשורה אחת לא משתנה") מתקיימת מאליה.
- **מגבלת אורך של `text-wrap: balance`:** חלק מהדפדפנים (כרום) מגבילים את
  היישום למספר שורות קטן (בסביבות 4-6) מטעמי ביצועים — לא רלוונטי כאן, כי אף
  כותרת באפליקציה לא מתקרבת לזה (כולן שורה או שתיים).

## Risks / Tradeoffs
- **שינוי גלובלי, לא per-component.** נוגע בכל שבעת ה-`h1` בבת אחת, כפי
  ש-product-spec דרש. הסיכון היחיד הוא ויזואלי (איך שורה נשברת) ולא פונקציונלי
  — אין סיכון לשבור התנהגות קיימת מעבר לאיך שהטקסט נראה כשהוא כבר נשבר לשתי
  שורות.
- **`h2` לא מטופל**, כפי שproduct-spec הגביל את ההיקף — אם תתגלה אותה תופעה
  ב-`h2` בעתיד, זו תוספת קטנה נפרדת (אותו כלל, סלקטור אחר), לא שינוי לתכנון הזה.

## Implementation Notes

נבנה בדיוק לפי המסמך — שורה אחת, `text-wrap: balance;`, בתוך כלל ה-`h1` הקיים
ב-`src/index.css`. שום קובץ אחר לא נגע.

אומת חזותית מול המקרה שדווח: הורצה גרסת `dev` אמיתית בדפדפן headless ברוחב
`390px` (iPhone), ומסך בחירת הכיתה של מיקה ("באיזו כיתה מתרגלים היום?") נבדק
לפני ואחרי. אחרי התיקון השבירה יוצאת "באיזו כיתה" / "מתרגלים היום?" — שתי שורות
קרובות באורכן, בלי מילה בודדת תלויה. צילום מסך נשמר ונבדק ידנית.

`npm run build`/`npm run lint` נקיים בגרסה `1.16.1` (`bump:fix`).

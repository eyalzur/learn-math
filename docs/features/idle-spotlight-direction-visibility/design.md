# זרקור-מנוחה — סדר לפי מיקום-מסך, ובולטות גבוהה יותר — Design

## Overview
רוויזיה לשני פרטים בלבד בזרקור-המנוחה הקיים ([idle-spotlight](../idle-spotlight/)):
סדר-הביקור בין הכרטיסים/כפתורים עובר מסדר-ה-DOM לסדר-מיקום-על-המסך (שורה
עליונה לפני תחתונה, ימין לפני שמאל בתוך שורה), ועוצמת-ה"נשימה" עולה עוד פעם
מעבר למה שכבר תוקן ב-`fix/idle-spotlight-dialog-reindex`. אין אפקט חדש, אין
מסך חדש — אותה "נשימה" (זוהר + גדילה זעירה) שכבר קיימת, רק יותר נראית וממוינת
אחרת.

## Screens / States
כל מסך שכבר מקבל את הזרקור היום (ראו idle-spotlight/design.md's "Screens /
States" — ללא שינוי: כל מסך עם כרטיסים/כפתורים לחיצים, מושהה בדיאלוג/מיקוד/
hover, זוהר-הרקע ממשיך תמיד).

**החדש:** על כל מסך כזה, ה*סדר* שבו הזרקור מבקר בכרטיסים נקבע עכשיו לפי
המיקום החזותי בפועל שלהם, לא לפי סדר-ה-DOM:
1. ממיינים את כל האלמנטים-המועמדים לפי המיקום-האנכי שלהם (`top` של
   ה-bounding box) — עליון קודם.
2. אלמנטים שה-`top` שלהם קרוב מספיק (חופפים אנכית — אותה "שורה" חזותית, גם אם
   לא מדויק פיקסל-בפיקסל, למשל גריד עם רווחים קטנים) מקובצים יחד ומסודרים
   ביניהם לפי המיקום-האופקי — ימני קודם (`right` גבוה יותר = קודם, תואם RTL).
3. התוצאה היא רשימה אחת, שורה-אחרי-שורה-מלמעלה, ימין-לשמאל בכל שורה — זו
   הרשימה שה-`--spot-i` נספר לפיה.

מסך עם שורה אחת בלבד (רוב מסכי-הכרטיסים הקיימים) בפועל לא משתנה חזותית מהיום —
ההבדל מורגש בעיקר במסכים עם יותר משורה אחת של כרטיסים (למשל רשימת-נושאים
ארוכה).

## Interaction Flow
זהה לזרימה הקיימת (רצף קבוע, ~שנייה לכרטיס, מחזור-מתמשך, מתחיל-מחדש בכל כניסה
למסך) — ראו idle-spotlight/design.md's "Interaction Flow". ההבדל היחיד: *איזה*
כרטיס הוא "הראשון" ו"הבא" נקבע לפי המיקום-על-המסך כמתואר למעלה, לא לפי סדר-ה-
DOM.

**עוצמת-ההדגשה** (`@keyframes idle-breathe`'s peak, היום `box-shadow: 0 5px 0
var(--accent-border), 0 0 0 9px var(--accent-bg), 0 0 26px var(--accent-border)`)
עולה פעם נוספת:
- טבעת-הזוהר (`0 0 0 9px`) → **`0 0 0 13px`**.
- הטשטוש (`0 0 26px`) → **`0 0 38px`**.
- גדילה זעירה (`transform: scale`) נשארת כפי שהיא — "יותר נראה" מתייחס לזוהר,
  לא לתזוזת-גודל (שזוהי כבר הייתה עדינה בכוונה ואין תלונה עליה).

כיוון מוחשי: קפיצה דומה בגודלה לקפיצה הקודמת (6px/18px → 9px/26px, ~50% גידול)
— שוב כ-45% גידול מהמצב הנוכחי, לא כפל. אם זה עדיין לא יספיק בעיני המשתמש
אחרי תצוגה מקדימה, זו כוונון-המשך קל, לא חסימה.

## Accessibility / RTL notes
"ימין-לפני-שמאל" כאן הוא כיוון-ביקור חזותי של אנימציה, לא כיוון טקסט/ביטוי-
חשבוני — אין תוכן LTR מעורב, אין סיכון bidi. המיון עצמו משתמש ב-
`getBoundingClientRect()` (מיקום-מסך בפועל, לא `direction`/`dir` לוגי), כך
שהתנהגותו זהה בכל רוחב-מסך ובכל כיוון-דפדפן. `prefers-reduced-motion: reduce`
ממשיך לכבות הכל לגמרי, ללא שינוי.

## Acceptance Criteria Check
- סדר-מעבר לפי מיקום-מסך (שורה עליונה קודם, בתוך שורה — ימין לפני שמאל): yes —
  ראו Screens/States, שלושת-השלבים.
- הסדר מתעדכן אוטומטית אם הפריסה משתנה: yes — ממשיך להישען על אותו מנגנון-
  reindex קיים (`MutationObserver`+`IntersectionObserver`, idle-spotlight/
  architecture.md's Revision section), רק מוסיף שלב-מיון לפני קביעת `--spot-i`
  — לא משנה מתי ה-reindex עצמו רץ.
- עוצמת-הדגשה בולטת יותר, עדיין "נשימה עדינה" לא הבהוב: yes — ראו הערכים
  הקונקרטיים למעלה (13px/38px), באותו יחס-גידול כמו התיקון הקודם שכבר אושר.
- שאר ההתנהגות (קצב, pause, viewport, reduced-motion) ללא שינוי: yes — שום
  דבר מהמתואר כאן לא נוגע בהם.

# המורה מבינה מה נכתב בדף — Design

## Overview
אותו דיאלוג קיים שנפתח בלחיצה על "שלח למורה" (תמונת הדף) מקבל תוסף: מתחת לתמונה
מופיע תיאור קצר, בשתי שורות מובחנות, של מה המורה קראה — השאלה ואז התשובה. אין מסך
חדש, אין ניווט נוסף. כשהקריאה לא ודאית, שתי השורות מתחלפות במשפט הודעה אחד. כפתור
🔊 קטן ליד התיאור מקריא אותו, לטובת מיקה.

## Screens / States

כל השינויים בתוך מסך המחברת הקיים (`PracticeNotebook`), במקום שכבר קיים בו הכפתור
"שלח למורה" והדיאלוג עם התמונה.

### 1. כפתור השליחה, בזמן המתנה
נשאר באותו מקום בסרגל הכלים. הטקסט בזמן המתנה משתנה כך שיתאים לפרסונה שכבר
קיימת באפליקציה ("המורה"), ולא ידבר על שליחה טכנית:

```
[ המורה קוראת... ]   (מנוטרל, כמו היום)
```

### 2. הדיאלוג — קריאה ברורה (המקרה הרגיל)
נפתח אחרי שהתשובה המלאה (תמונה + תיאור) חזרה — לא בשני שלבים נפרדים, כדי שלא
ייפתח דיאלוג עם "חצי תשובה" שמשתנה מתחתיו.

```
┌─────────────────────────────────────┐
│  זה הדף שהמורה מסתכל עליו             │
│  [ תמונת הדף, כמו היום ]              │
│                                        │
│  מה המורה הבינה                🔊     │
│  מה שכתבת: 7 + 5=                     │
│  התשובה שרשמת: 12                     │
│                                        │
│              [ סגירה ]                │
└─────────────────────────────────────┘
```

שתי השורות (מה שכתבת / התשובה שרשמת) תמיד מוצגות זו מתחת לזו, לא באותה שורה
ולא מוזגות למשפט אחד — זו הדרישה של המפרט שהן יהיו "מובחנות בבירור זו מזו".

### 3. הדיאלוג — קריאה לא ודאית
כשהמורה לא בטוחה מה נכתב (כתב לא ברור, יותר מתשובה אחת, דף כמעט ריק), שתי
השורות של מקרה 2 מוחלפות **במשפט אחד**, במקום להציג ניחוש:

```
┌─────────────────────────────────────┐
│  זה הדף שהמורה מסתכל עליו             │
│  [ תמונת הדף, כמו היום ]              │
│                                        │
│  לא הצלחתי לקרוא את זה בבירור.        │
│  אפשר לכתוב שוב, קצת יותר גדול         │
│  או ברור?                             │
│                                        │
│              [ סגירה ]                │
└─────────────────────────────────────┘
```

בלי כפתור 🔊 כאן — אין עדיין שני משפטים קבועים להקריא; ראו Open Questions.

### 4. כישלון תקשורת (לא הגיע מענה כלל)
זהה למצב הקיים היום: הדיאלוג לא נפתח בכלל, ומופיעה שורת השגיאה הקיימת מתחת
לסרגל הכלים (ללא שינוי): "לא הצלחנו לשלוח את הדף. נסו שוב." שאר המחברת (כתיבה,
מחיקה, ניווט דפים) נשארת פעילה מסביב.

## Copy

מחרוזות חדשות/משתנות בלבד — הכל עברית, בלי אף מילה מהעולם הטכני:

- כפתור בזמן המתנה: `המורה קוראת...` (מחליף את `שולח...` הקיים)
- כותרת קטנה מעל התיאור: `מה המורה הבינה`
- תווית לשורת השאלה: `מה שכתבת:`
- תווית לשורת התשובה: `התשובה שרשמת:`
- הודעת אי-ודאות (מחליפה את שתי השורות למעלה כשיש): `לא הצלחתי לקרוא את זה
  בבירור. אפשר לכתוב שוב, קצת יותר גדול או ברור?`
- `aria-label` לכפתור ההקראה: `הקראת מה שהמורה הבינה`
- ללא שינוי: כותרת הדיאלוג `זה הדף שהמורה מסתכל עליו`, כפתור `סגירה`, שורת
  השגיאה `לא הצלחנו לשלוח את הדף. נסו שוב.`

## Interaction Flow

1. תלמיד/ה כותב/ת בדף ולוחצ/ת "שלח למורה" (ללא שינוי מהיום).
2. הכפתור מנוטרל ומציג "המורה קוראת..." עד לתשובה.
3. **תשובה תקינה, קריאה ברורה** → נפתח הדיאלוג עם התמונה למעלה, ומתחתיה הכותרת
   "מה המורה הבינה" ושתי השורות (שאלה, תשובה). לחיצה על 🔊 מקריאה את שתי השורות
   ברצף ("מה שכתבת: … התשובה שרשמת: …"), באותו דפוס הקראה שכבר קיים בהסברים.
   לחיצה על "סגירה" סוגרת את הדיאלוג וחוזרת לדף לכתיבה נוספת.
4. **תשובה תקינה, קריאה לא ודאית** → אותו דיאלוג, אבל השורות מוחלפות במשפט
   אי-הוודאות. "סגירה" סוגרת; התלמיד/ה יכול/ה לכתוב שוב ביתר בהירות ולנסות שוב.
5. **הבקשה נכשלת** (רשת/שרת/timeout) → הדיאלוג לא נפתח כלל; שורת שגיאה קבועה
   מופיעה מתחת לסרגל הכלים, בדיוק כמו כישלון השליחה הקיים היום. אין הבחנה
   כלפי התלמיד/ה בין "השרת לא ענה" לבין "המורה לא הצליחה לקרוא" מבחינה טכנית —
   שתיהן מוצגות כאותה שורת שגיאה, כי מבחינת התלמיד/ה זו אותה חוויה ("לא קיבלתי
   תשובה"), בעוד שקריאה לא ודאית (מצב 4) *היא* תשובה, ולכן מוצגת בתוך הדיאלוג.

## Accessibility / RTL notes

- **הביטויים החשבוניים בשתי השורות (`7 + 5=`, `12`) חייבים בידוד LTR נפרד מהטקסט
  העברי סביבם** — בדיוק אותו באג שקרה שלוש פעמים בעבר בפרויקט. התיאור מגיע ממודל
  שפה כטקסט חופשי, ולכן על השרת לסמן בפלט אילו קטעים הם חשבון (באותו מוסכם
  שהאפליקציה כבר משתמשת בו לטקסט מעורב — סימון בגרשיים אחוריים סביב ביטוי), כדי
  שהלקוח יציג כל קטע כזה מבודד ומיושר משמאל לימין, בלי לתת לאלגוריתם ה-bidi
  הכללי של הדפדפן לגעת בו. זו דרישת תצוגה, לא רק ניסוח — "7 + 5" שמוצג הפוך
  בתוך המשפט העברי הוא כשל באותה מידה כמו טעות בתוכן.
- שתי השורות (שאלה/תשובה) הן שני אלמנטים נפרדים בעץ ה-DOM, לא מחרוזת אחת עם
  שבירת שורה — אותו כלל פרויקטלי: טקסט עברי וביטוי חשבוני (וכאן, שתי יחידות
  מידע נפרדות) לא מתערבבים במחרוזת אחת.
- הודעת אי-הוודאות אינה מכילה חשבון כלל, ולכן אינה צריכה בידוד.
- כפתור ה-🔊 מקבל `aria-label` מפורש (לא רק אייקון), ומצב "מקריא כרגע" מסומן
  ויזואלית (⏹ במקום 🔊), כמו שכבר קיים במנגנון ההקראה של ההסברים.
- שורת האי-ודאות והתיאור התקין מסומנים `aria-live="polite"` כשהם מתווספים
  לדיאלוג, כמו שורת השגיאה הקיימת של השליחה.

## Acceptance Criteria Check

- לחיצה על "שלח למורה" מציגה גם תיאור קצר, עם שאלה ותשובה מובחנות: **yes** —
  מסך 2, שתי שורות נפרדות.
- אין קביעת נכון/שגוי בתשובה: **yes** — הכותרות והתוויות מדווחות רק "מה נקרא",
  בלי מילת שיפוט אחת.
- קריאה לא ודאית נאמרת בפירוש, לא מוצגת כניחוש ודאי: **yes** — מסך 3.
- התיאור נאמן למה שנכתב, בלי תוספת: **partial** — זו בעיקר החלטת ניסוח בפרומפט
  של השרת (tech-lead/developer), לא משהו שהעיצוב יכול להבטיח לבד; העיצוב לפחות
  לא מזמין תוספות (שתי שורות עובדתיות בלבד, לא פסקה חופשית).
- הפעולה נשארת יזומה במפורש: **yes** — לא נוסף שום טריגר אוטומטי.
- זמן המתנה מוגבל וברור, עם שגיאה ברורה בכישלון, בלי לתקוע את שאר המחברת: **yes**
  — מסך 1 (מצב טעינה) ומסך 4 (שגיאה); מספר השניות המדויק לפני timeout הוא
  החלטה טכנית של tech-lead, לא עיצובית.
- בלי מפתח/סוד בלקוח: **n/a לעיצוב**.
- בלי מונחי תשתית לתלמיד/ה: **yes** — כל המחרוזות החדשות נבדקו (ראו Copy).

## Open Questions
None — כל מה שהמפרט השאיר פתוח הוכרע למעלה (כן הקראה בקול; מבנה קבוע של שתי
שורות ולא טקסט חופשי; הודעת אי-ודאות ייעודית; כישלון תקשורת ממופה לשורת השגיאה
הקיימת ולא למסך חדש).

# שיעור על סגנון תרגיל — Architecture

## Overview
שדה `style` על השאלות, טבלת שמות במודול נפרד, מסך בחירה חדש — ו**שיעור שהוא
מבנה זהה למה ש-`Practice` כבר מקבל**, כך שמסך התרגול, מסך הסיום ורישום ההיסטוריה
אינם משתנים כלל.

## Affected Files / Components

| קובץ | מה משתנה |
|---|---|
| `src/data/style.ts` | **חדש.** `STYLE_META` (מזהה → שם עברי), `stylesOf(topic)` שמקבץ שאלות לסגנונות, וטיפוס `Lesson`. |
| `src/data/curriculum.ts` | `style?: string` על `Question`, וטיפוס `StyledQuestion` שבו הוא **חובה**. |
| `src/data/grade1.ts` | `style` על כל `150` השאלות, והצהרת הנושאים דרך `StyledQuestion`. |
| `src/components/StylePicker.tsx` | **חדש.** מסך הכרטיסים עם הדוגמה, ההקראה והמספר. |
| `src/components/Practice.tsx` | ה-prop `level: Level` נעשה `lesson: Lesson`. אין שינוי אחר. |
| `src/components/Result.tsx` | אותו שינוי prop. |
| `src/App.tsx` | ענף `styles` ב-`Screen`, וניתוב שמדלג עליו בנושא חד-סגנוני. |
| `src/App.css` | `.style-grid`, `.style-card`, `.style-example`. |
| `tests/e2e/content.spec.ts` | כללים סופרים — עבודת QA. |

**`src/data/progress.ts` ו-`src/components/History.tsx` אינם משתנים.** ראו הכרעה `5`.

## Data / State Changes

```ts
// curriculum.ts
export interface Question {
  // …
  /** Which kind of exercise this is — see `style.ts`. Required in every grade that has
   *  been classified; see the note on StyledQuestion. */
  style?: string;
}

/** A question whose style has been decided. Grade 1 declares its content through this. */
export type StyledQuestion = Question & { style: string };

// style.ts
export interface Lesson {
  title: string;
  questions: Question[];
}

export interface Style {
  id: string;
  title: string;
  /** The first question of the style — the card's example. Derived, never written. */
  example: Question;
  questions: Question[];
}
```

`Level` נשאר כפי שהוא ואינו נוגע.

## Technical Approach

### 1. חובה — אבל באתר ההצהרה, לא על הטיפוס המשותף

הספק דורש ש"הקומפיילר יסרב לשאלה שאין לה סגנון, בדיוק כמו `analogy`". הבעיה
שהתגלתה כשירדתי לקוד: **`Question` משותף ל-`510` שאלות, וגל א׳ מסווג `150`.**
שדה חובה על הטיפוס המשותף מפיל את הקומפילציה על `360` שאלות בכיתות ו׳ ו-ח׳,
שהספק הוציא מהגל הזה **במפורש ומסיבה טובה** — הסיווג שם דורש שיקול דעת אנושי
וכתיבת שאלות חדשות.

שלוש דרכים, ואחת מהן נכונה:

| | מה קורה |
|---|---|
| חובה על `Question` עכשיו | צריך לנחש `360` סגנונות היום. **הספק אוסר.** |
| `style?:` אופציונלי, וזהו | שאלה חדשה בכיתה א׳ בלי סגנון מתקמפלת. **בדיוק מה שהספק בא למנוע** — "אופציונלי הופך שכחה לאישור". |
| **אופציונלי על המשותף, חובה באתר ההצהרה** | `grade1.ts` מצהיר דרך `StyledQuestion`, ושאלה בלי `style` שם **אינה מתקמפלת**. ו׳ ו-ח׳ מתקמפלים כפי שהם. |

**נבחר השלישי.** מצב הכשל שהספק חושש ממנו — שאלה חדשה של מיקה שנשמטה בלי סגנון
— **אינו קיים**, כי הקומפיילר עוצר אותה בקובץ שבו היא נכתבת. האופציונליות חיה
רק על הטיפוס המשותף, ורק כל עוד יש כיתה שטרם סווגה.

**וכשגל ב׳ ינחת:** אותו הידוק על `grade6.ts` ו-`grade8.ts`, ואז `style` עובר
להיות חובה על `Question` עצמו ו-`StyledQuestion` נמחק. **זה מסלול, לא ויתור
קבוע** — ורצוי שגל ב׳ יסיים בו.

### 2. הסגנונות נגזרים; השמות מוצהרים

חלוקה נכונה בין מה שהמכונה יכולה לדעת לבין מה שאדם החליט:

| | מאיפה |
|---|---|
| **לאילו סגנונות נחלק הנושא** | נגזר: קיבוץ שאלות לפי `style`. |
| **הסדר בין הסגנונות** | נגזר: סדר ההופעה הראשונה בנתונים. |
| **מספר השאלות** | נגזר: אורך הקבוצה. |
| **הדוגמה על הכרטיס** | נגזר: **השאלה הראשונה בקבוצה** אחרי המיון. |
| **השם העברי** | **מוצהר** ב-`STYLE_META`. אינו נגזר משום דבר. |

`stylesOf(topic)` עובר על `topic.levels` **בסדר `easy → medium → hard`**, מקבץ
לפי `style`, ומחזיר `Style[]`. המיון הזה הוא גם מה שמספק את דרישת הספק
ששאלות השיעור מסודרות מהקלה לקשה — **הוא נופל מהמעבר עצמו ואינו מיון נוסף.**

**מזהי הסגנונות ייחודיים גלובלית ולא לפי נושא** — `add10` ו-`add20`, לא `add`
פעמיים. הספק קובע שסגנון שייך לנושא אחד, ושמות חוזרים ("חיבור" בשני נושאים) הם
שני סגנונות; מזהה ייחודי הופך את זה למובן מאליו ומונע מפתח כפול ב-`STYLE_META`.

`stylesOf` מסנן סגנונות עם פחות מ-`3` שאלות, כדרישת הספק. בנתונים של מיקה אין
כזה, והמסנן קיים כדי ששאלה שתועבר נושא לא תיצור שיעור בן שתיים בשקט.

### 3. `style.ts` נפרד — אותה מלכודת בדיוק, אותו פתרון

CLAUDE.md מתעד מסך לבן ש-TypeScript לא תפס: `grade1.ts` קרא ל-`level()` ב-
`curriculum.ts`, שמייבא את `grade1.ts` בחזרה. לכן `level()` יושב ב-`level.ts`.

**`grade1.ts` יצטרך את מזהי הסגנונות, ו-`STYLE_META` יצטרך להיות נגיש למסך —
בדיוק אותה צורה.** לכן `STYLE_META` ו-`stylesOf` יושבים ב-`src/data/style.ts`,
ש**מייבא טיפוסים בלבד** (`import type`) ולכן אינו יכול ליצור קשת ריצה.

**ו-`grade1.ts` לא יייבא ממנו כלום.** המזהים נכתבים כמחרוזות (`style: "after"`),
והקשר בין המחרוזת ל-`STYLE_META` נאכף בבדיקה ולא בקומפיילר. זה מכוון: ייבוא
לצורך קבועים בלבד הוא בדיוק הקשת שהפילה את הפרויקט פעם אחת. **בדיקת QA שכל
`style` בנתונים קיים ב-`STYLE_META` ולהפך** קונה את אותו ביטחון בלי הקשת.

### 4. `Lesson` — וזו הסיבה שמסך התרגול אינו משתנה

`Practice` ו-`Result` מקבלים היום `level: Level`, ומשתמשים ממנו ב-`title`
וב-`questions` בלבד. `Level` הוא `{ id, title, description, questions }`.

**מצמצמים את ה-prop לטיפוס המבני המינימלי:**

```ts
export interface Lesson { title: string; questions: Question[]; }
```

`Level` מתאים לו מבנית כפי שהוא — אין המרה, אין עטיפה, ואתרי הקריאה הקיימים
ממשיכים להעביר `Level`. שיעור על סגנון הוא `{ title: styleTitle, questions }`,
ומכאן **מסך התרגול, מסך הסיום, ההקראה, האבחון, הציורים ורישום ההיסטוריה עובדים
בלי שורה אחת של שינוי.**

החלופה — להרחיב את `Level["id"]` במזהה נוסף — הייתה מחלחלת ל-`levelClass`
ב-`LevelPicker`, ל-`LEVEL_META` ולכל מקום שממפה שלוש רמות, בשביל ערך שאינו רמה.

### 5. הניווט — נגזר מהנושא, בלי state נוסף

```ts
type Screen =
  | { name: "home" }
  | { name: "levels"; topic: Topic | null }
  | { name: "styles"; topic: Topic }          // חדש
  | { name: "history" }
  | { name: "practice"; topic: Topic | null; lesson: Lesson }
  | { name: "result";   topic: Topic | null; lesson: Lesson; correctCount: number };
```

**החזרה אינה זוכרת מאיפה באת — היא מחשבת לאן.** נושא רב-סגנוני חוזר ל-`styles`,
חד-סגנוני ל-`levels`, וזה נגזר מ-`stylesOf(topic).length >= 2` — אותו תנאי בדיוק
שקבע לאן ללכת בהתחלה.

זה נכון ולא רק קצר: `origin` ששמור ב-state יכול להתפגר מול הנתונים ולהחזיר ילד
בן שבע למסך שלא היה בו. **פונקציה של הנושא אינה יכולה.**

בחירת נושא ב-`TopicPicker` מנתבת לפי אותו תנאי, ולכן "חיבור עד `10`" ממשיך
ישירות ל-`LevelPicker` ואינו רואה את המסך החדש כלל.

### 6. `progress.ts` — לא נוגעים, ובכוונה

היום נשמר `{ topicTitle, levelTitle }` ו-`History` מרנדר `נושא · רמה`.

שיעור על סגנון שומר את **שם הסגנון** ב-`levelTitle`, ומקבל `מספרים עד 20 · מה
בא אחרי` — בדיוק מה שהעיצוב דורש, **בלי שינוי ב-`progress.ts` וב-`History.tsx`
ובלי מיגרציה.**

שקלתי `styleTitle?` נפרד ודחיתי: הרשומות **כבר יושבות ב-localStorage אצל שלושת
הילדים**, ושדה חדש היה מחייב נפילה לאחור בכל אתר קריאה — סיבוכיות אמיתית בשביל
דיוק שמי בלבד. **המחיר שכן משולם:** השם `levelTitle` נעשה רחב יותר ממה שהוא
אומר, והתיעוד שלו מתוקן לכך במפורש ("מה תורגל — רמה או סגנון").

אם גל ב׳ או "אבחון לאורך זמן" יצטרכו להבחין בין השניים, `styleId?` אופציונלי
נוסף אז בלי מיגרציה — רשומה ישנה בלעדיו היא בדיוק מה שהיא היום.

## Edge Cases
- **נושא חד-סגנוני** — `stylesOf` מחזיר אחד, המסך אינו מוצג, והחזרה מחשבת
  `levels`. שני נושאים בנתונים.
- **סגנון עם פחות מ-`3` שאלות** — מסונן. אינו קיים בנתונים היום.
- **נושא שכל סגנונותיו סוננו** — נופל ל-`levels`, כי התנאי הוא על התוצאה של
  `stylesOf` ולא על מה שהיה לפני הסינון.
- **שאלה בלי `style` בנושא של מיקה** — בלתי אפשרית: `StyledQuestion` עוצר בקומפילציה.
- **`style` שאין לו ערך ב-`STYLE_META`** — אפשרי בקומפילציה (אין ייבוא), ולכן
  **בדיקת QA משני הכיוונים** היא מה שסוגר את זה.
- **כיווניות** — הדוגמה עוברת ב-`promptSegments` ובאותו רינדור מבודד של
  `.problem-text`, ולא כמחרוזת ב-`<span>`. שמות הסגנונות נבחרו בלי ספרות ולכן
  אינם יכולים להישבר. זו המלכודת שנשלחה כאן שלוש פעמים.
- **כפתור ההקראה בתוך כרטיס שהוא `button`** — כפתור בתוך כפתור אינו חוקי ב-HTML.
  הכרטיס נבנה כ-`div` עם `role="button"` ו-`tabIndex`, או שההקראה יוצאת מחוץ
  לגבול הלחיץ. **הכרעה: הכרטיס הוא `button`, וכפתור ההקראה יושב לצידו ולא בתוכו**
  — פריסה שמשאירה את שניהם אלמנטים חוקיים ובנפרד בסדר המקלדת.

## Risks / Tradeoffs
- **`style?` אופציונלי על `Question`** הוא חוב מוצהר עם מסלול פירעון (הכרעה `1`),
  ולא הכרעה קבועה. אם גל ב׳ לא יגיע, החוב נשאר — וזה הסיכון האמיתי כאן.
- **המזהים אינם מיובאים ל-`grade1.ts`**, ולכן שגיאת כתיב במזהה אינה נתפסת
  בקומפילציה אלא בבדיקה. נבחר במודע מול הקשת המעגלית שכבר הפילה את הפרויקט.
- **`levelTitle` נושא גם שם סגנון.** שם שדה שרחב ממה שהוא אומר, מול מיגרציה של
  נתונים חיים אצל שלושה ילדים.
### מה נשבר — נמדד, לא הוערך
`.level-card` מופיע **`33` פעמים ב-`15` קבצי בדיקה**. כל בדיקה שנכנסת לאחד
משלושת הנושאים הרב-סגנוניים של מיקה תמצא שם `.style-card` ותיפול.

| קובץ | `.level-card` | מזכיר את מיקה |
|---|---|---|
| `topics-and-progress.spec.ts` | `8` | `10` |
| `mistake-diagnosis.spec.ts` | `4` | `1` |
| `review-status.spec.ts` | `3` | `5` |
| `students-and-syllabus.spec.ts` | `3` | `3` |
| `fraction-diagram.spec.ts` · `mistake-explanation.spec.ts` · `teaching-explanations.spec.ts` · `version-number.spec.ts` | `2` כל אחד | |
| שבעה קבצים נוספים | `1` כל אחד | |

**מה שאינו נשבר, וזה הרוב:** כל מה שנוגע בכיתות ו׳ ו-ח׳ (אין להן `style`, ולכן
`stylesOf` מחזיר ריק והמסלול נשאר `levels`), וכל מה שנוגע ב"חיבור עד `10`"
ו"חיסור עד `10`" של מיקה — חד-סגנוניים.

**זה מחיר אמיתי של ההכרעה "הסגנון מחליף את הרמה"**, והוא נרשם כאן כדי שלא ייראה
כהפתעה כשהסוויטה תאדים. הוא אינו טענה נגד ההכרעה: `.style-card` הוא מסך אחר עם
תוכן אחר, ובדיקה שתמשיך לחפש `.level-card` שם תהיה בדיקה שמתארת מסך שאינו קיים.
**המספר המדויק של הבדיקות שייפלו יגיע מהרצה, לא מהערכה** — הספירה כאן היא של
אתרי קריאה, וחלקם בתוך פונקציות עזר שמשרתות כמה בדיקות.

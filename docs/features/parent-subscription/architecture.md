# מנוי הורים — Architecture

> עודכן 2026-11-26 אחרי ההחלטות: משתמשים מאפס בדאטאבייס בלבד, ושאלות בשרת. הגרסה הקודמת (offline-first עם `localStorage` כמקור אמת וסנכרון ברקע) **בוטלה**.

## Overview
- **דאטאבייס:** Firebase (Auth + Firestore, ובשלב 4 Cloud Messaging) — מקור האמת היחיד. אין `localStorage` של משתמשים, היסטוריה או הגדרות.
- **שרת שאלות:** שירות חדש ב-Cloud Run (אותו דפוס כמו `server/` של ההקראה: Node+Express, פריסה ב-GitHub Actions עם Workload Identity, בלי סוד בריפו). מייצר שאלות מהטמפלייטים (`adaptive*.ts`, `grade*.ts`), מחזיק את הרמה המסתגלת, ושומר תוצאות.
- **שתי אפליקציות (הוכרע 2026-11-27):** הילדים בשורש האתר (`/`), ההורים בנתיב נפרד (`/parents/`, דף ו-`manifest-parents.json` משלו כדי שיותקנו בנפרד). אותו קוד ואותו שרת; אין שום מסך הורים בחבילת מסך הילדים של הניווט, ולא להפך. מפתחות אחסון נפרדים לכל תפקיד (`learn-math:cloud-parent-token` / `-child-token`).
- **דפדפן:** מציג, מקליד, ומחשב הסברים וציורים מהנתונים שהשרת מחזיר. האתר עצמו נשאר קבצים סטטיים ב-GitHub Pages.
- **מה כן נשמר במכשיר:** אסימון חיבור אחד (איזה ילד המכשיר הזה) והעדפות תצוגה של המכשיר, אם יהיו. לא נתוני ילד.
- **שער המנוי נאכף בשרת:** כשהמנוי פג — השרת לא נותן שאלה. אי אפשר לעקוף מהדפדפן.

## Technical Approach
1. **הורה:** התחברות Firebase Auth (גוגל + קישור במייל) ← יצירת משק בית ← ניסיון.
2. **ילד:** ההורה מציג קוד, הילד מקליד במכשיר שלו; המכשיר מקבל התחברות אנונימית קשורה ל-`childId`. בלי סיסמה לילד. אצל מיקה ההורה מקליד על המכשיר.
3. **תרגול:** הדפדפן מבקש שאלה מהשרת (עם אסימון הילד). השרת בודק מנוי ← מחשב רמה ← מחזיר שאלה (כולל הנתונים להסבר/ציור). תשובה נשלחת לשרת; מי מאמת — שאלה פתוחה 3 במפרט.
4. **"הילד לא ממתין":** הכלל הישן ("אל תחכה לשרת") כבר לא ניתן לקיום; מה שנשמר ברוחו — טעינה מקדימה של השאלה הבאה, ומסך טעינה קצר וחלק במקום ריק או קפוא.
5. **כללי אבטחה:** הורה קורא ומשנה רק את משק הבית שלו; ילד מגיע לדאטאבייס **רק דרך שרת השאלות**, לא ישירות. מגבלות 2/3 נאכפות בשרת.
6. **מנוי שפג:** שרת השאלות מחזיר "מנוי לא פעיל" ← מסך עצירה פשוט בלי טקסט מפחיד (הוכרע: הילד לא מתרגל).
7. **מחיקת ילד:** Function מוחקת את כל `children/{cid}` ותת-האוספים וקודי חיבור שלו.

## Edge Cases
- אין אינטרנט באמצע תרגול: הודעה קצרה ופשוטה ("אין חיבור"), חזרה אוטומטית כשחוזר. תשובות שכבר נשלחו לא אובדות.
- שני מכשירים לאותו ילד: מזהה תרגול ייחודי למניעת כפילות.
- קוד חיבור שפג או נוחש: הגבלת ניסיונות לכל משק בית.
- מחיקת ילד באמצע תרגול: המכשיר חוזר למסך הקוד.
- ספרות קוד ומחירים: `direction: ltr` + `unicode-bidi: isolate`.
- הפסקה במנוי באמצע תרגול: השאלה הבאה נחסמת; תשובה שכבר נשלחה נשמרת.

## Risks / Tradeoffs
- **תלות מוחלטת בשרת ובאינטרנט** לכל תרגול. זה שינוי מהותי מהאפליקציה היום (סטטית, עובדת ללא רשת) — אתר פעיל שלושה ילדים אמיתיים שיפסיקו לתרגל בכל תקלה. מחייב: ניטור, התראה על תקלות, ובדיקת עומס/זמן תגובה (cold start ב-Cloud Run; שקול `min-instances=1`).
- **עלות:** Cloud Run + Firestore לפי שימוש; Blaze. Budget alert חובה.
- **העברת הטמפלייטים:** 740KB של בנקי שאלות ו-12 מחוללים כתובים ב-TypeScript בצד הלקוח. אפשרות: חבילה משותפת שגם הלקוח (להסברים) וגם השרת מייבאים. החלטה ל-`tech-lead`; הסיכון: שבירת `analogy` חובה, RTL ו-`promptSegments`.
- **פרטיות קטינים:** נתונים מצומצמים (כינוי+התקדמות); מדיניות ונוסח משפטי — מהמשתמש.
- **נעילה לספק** (Firebase) — מקובל. ספק תשלום ישראלי נבחר רק בשלב 5.
- **iOS Push:** מוגבל ל-PWA מותקן (שלב 4).

## הגדרת Firebase — מה נדרש מהמשתמש
**לפיתוח שלב 1 לא נדרש כלום:** כותבים ובודקים מול Firebase Emulator מקומי, בלי חשבון. הצעדים הבאים נדרשים רק כדי לנסות את זה "חי" (Claude לא יוצר חשבונות ולא מקבל סיסמאות):

1. **להגיד איזה פרויקט Firebase לחבר:** הפרויקט הקיים ב-GCP (`learn-math-506923`) או אחר. מה שצריך ממנו: **מזהה הפרויקט**.
2. **להוסיף "Web app"** בפרויקט (Firebase Console ← Project settings) ולהעביר את אובייקט ה-`firebaseConfig` (`apiKey`, `authDomain`, `projectId`, `appId`…). אלה מזהים ציבוריים ולא סודות — מותר שיהיו בקוד של הדפדפן; אבטחה באה מ-`firestore.rules`.
3. **Authentication ← Sign-in method:** להפעיל **Google** ו-**Email link (passwordless)**.
4. **Authentication ← Settings ← Authorized domains:** להוסיף `eyalzur.github.io`.
5. **Firestore Database:** ליצור (Production mode). **אזור נקבע פעם אחת ואי אפשר לשנות** — המלצה `me-west1` (תל אביב) אם זמין, אחרת `europe-west`. להודיע לי איזה נבחר.
6. **תוכנית Blaze (תשלום לפי שימוש):** נדרשת ל-Cloud Functions (קוד חיבור — כבר בשלב 1, ותזכורות — שלב 3). להגדיר **Budget alert** (למשל 5$) ב-GCP Billing.
7. **שלב 3 בלבד:** Cloud Messaging ← Web Push certificates ← ליצור מפתח VAPID ולהעביר את המפתח **הציבורי**.
8. **פריסה (לפני "חי"):** בדומה לשרת המחברת — חשבון שירות ו-Workload Identity Federation ל-GitHub Actions, שיפרוס `firestore.rules` ו-`functions/` בלי סוד בריפו. את זה נכתוב יחד כשמגיעים לשם.

## Implementation Notes (2026-11-27)
נבנה כ**מצב ענן** שנדלק רק בבנייה (`VITE_CLOUD=1` מול שרת, `VITE_CLOUD=mock` — אותו קוד שרת רץ בתוך הדף, לתצוגה מקדימה). בלי הדגל האתר החי נשאר האפליקציה הישנה, כך שאפשר לבדוק לפני שמחליפים.

**מבנה:**
* `src/cloud/server/` — כל הלוגיקה (`service.ts`), חנות מסמכים (`store.ts`), טיפוסים וממשק `CloudApi`. קוד זהה בשרת ובדמו בדפדפן.
* `api/` — Express דק + אימות (Firebase ID token / `dev:<email>` ב-`DEV_AUTH`) + אסימוני מכשיר ילד חתומים (HMAC) + מתאם Firestore. הלוגיקה מיובאת מ-`src/`.
* `src/cloud/` — `CloudApp` (כניסה, שער הורים, התחברות), `ParentApp` (בית, ילד, לוח זמנים, תזכורת, מנוי, חיבורים, פרטיות), `ChildApp` (בורר נושאים, `Practice`/`Result`/`SettingsDialog` הקיימים, מסך עצירה, הודעות).
* מה שנשאר במכשיר: אסימון חיבור הילד בלבד (ובמצב בדיקה אסימון הורה).

**סטיות מהתכנון, בגלוי:**
1. **התראות:** במקום Push (FCM), ההודעה נשמרת בתיבה של הילד והמכשיר קורא אותה בכל כניסה/רענון ובדגימה כל 30 שניות. FCM לא נבנה — אי אפשר לבדוק אותו כאן, ו-iOS דורש PWA מותקן. נשאר לשלב המשך.
2. **אימות תשובה:** נשאר בדפדפן (`Practice` כמו היום). השרת מחליט אילו שאלות הילד מקבל, שומר את הרמה וההתקדמות, ומסרב כשהמנוי פג — אבל לא מסתיר את התשובות. החלטה טכנית שנדחתה (מסתיר תשובות = שינוי ב-`Practice` ובהסברים).
3. **שאלות בשרת, אבל חבילת הלקוח עדיין מכילה את הבנקים** (ל-`curriculum.ts`: רשימת נושאים, שיעורים, הסברים). הוצאת ה-740KB מהחבילה היא שלב נפרד.
4. **נושאים לא-אדפטיביים** (רמות/סגנונות כתובים מראש): השרת מגיש כרגע את הרמה הראשונה בלבד, בלי בורר רמה/סגנון ובלי מסך שיעור לפני התרגול ("שיעור קודם").
5. **חלון פעיל:** אם המנוי נגמר באמצע ריצה, התשובה נשמרת והילד מגיע למסך העצירה רק בסיום/יציאה (לא באמצע המשוב).
6. **מגבלת ניחושי קוד:** 10 ניסיונות כושלים ל-10 דקות לכתובת (בזיכרון, לא משותף בין מופעי Cloud Run).
7. **פתוח לשלב ההחלפה:** מחיקת הקוד הישן (`userStore`, `lessonAllowance`, `StudentPicker`, מגירת פרופיל/היסטוריה מקומית) ו-~490 הבדיקות הקיימות שמניחות `localStorage` — רק אחרי שהמשתמש בודק את מצב הענן ומחליט להחליף.

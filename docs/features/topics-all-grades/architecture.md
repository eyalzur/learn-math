# בחירת נושא לכיתות ו׳ ו-ח׳ — Architecture

## Overview
שני קבצי תוכן חדשים בתבנית של `grade1.ts`, ו-`Grade` מפסיק להיות איחוד מבחין
וחוזר להיות טיפוס אחד — כי אחרי השינוי כל שלוש הכיתות מתרגלות לפי נושא ולענף
השני לא נשאר אף מקרה.

## Affected Files / Components
- **`src/data/grade6.ts`** (חדש) — 6 נושאים × 3 רמות × 5 שאלות.
- **`src/data/grade8.ts`** (חדש) — אותו מבנה.
- **`src/data/curriculum.ts`** — `grade6` ו-`grade8` עוברים ל-`practice: "topics"`
  ומצביעים על הקבצים החדשים; 60 השאלות המוטבעות בו נמחקות משם (הן עוברות לקבצים);
  `Grade` מאבד את האיחוד.
- **`src/App.tsx`** — שתי נקודות ההסתעפות על `practice` נמחקות (שורות 79 ו-148).
- **`src/data/level.ts`, `src/data/grade1.ts`, `src/components/*`, `src/App.css`** —
  **ללא שינוי.**
- **`package.json`** — `1.1.0` → `1.2.0` דרך `npm run bump:feature`.

## Data / State Changes

### `Grade` מפסיק להיות איחוד מבחין

היום:
```
Grade = { id, label, topics: string[] } & (
  | { practice: "topics"; topicSets: Topic[] }
  | { practice: "levels"; levels: Level[] }
)
```
אחרי: שדה `practice` והענף `levels` נמחקים; נשאר `topicSets: Topic[]` תמיד.

**למה למחוק ולא להשאיר.** האיחוד הוכנס כדי שהקומפיילר יכריח כל צרכן לטפל בשתי
הצורות בזמן שהיו שתי צורות. אחרי הפיצ'ר הזה אין אף כיתה עם `practice: "levels"` —
כלומר איחוד עם מאכלס אחד, שהוא לא איחוד. להשאיר אותו פירושו שכל צרכן ממשיך לשאת
ענף **שאי אפשר להגיע אליו ולכן אי אפשר לכסות בבדיקה**, וקוד לא-מגיע-אליו הוא בדיוק
מה שנרקב בשקט. האיחוד עשה את עבודתו במעבר, והמעבר נגמר.

המחיקה זולה מכפי שהיא נשמעת: **רק שתי נקודות בקוד כולו מסתעפות על `practice`**,
שתיהן ב-`App.tsx`. נבדק, לא הונח.

## Technical Approach

### מיחזור 60 השאלות הקיימות — כן

ספרתי את ההתפלגות בפועל של 30 השאלות בכל כיתה לפי נושא ורמה. **לכל שאלה קיימת
כבר יש `topic`, `steps` ו-`analogy`**, וכל אחת נופלת לתא מוגדר. אין סיבה לזרוק
תוכן שכבר עבר ביקורת ולכתוב אותו מחדש — הוא עובר לקבצים החדשים כמות שהוא, ומשלימים
כל תא ל-5.

**מה חסר בפועל (זו רשימת העבודה של ה-developer):**

כיתה ו׳ — קיים / להוסיף, לפי `קל · בינוני · מתקדם`:

| נושא | קיים | להוסיף |
|---|---|---|
| שברים פשוטים | 3 · 2 · 2 | 2 · 3 · 3 |
| שברים עשרוניים | 2 · 2 · 2 | 3 · 3 · 3 |
| אחוזים | 2 · 2 · 2 | 3 · 3 · 3 |
| יחס ופרופורציה | 0 · 1 · 1 | 5 · 4 · 4 |
| שטח והיקף | 2 · 2 · 2 | 3 · 3 · 3 |
| ממוצע | 1 · 1 · 1 | 4 · 4 · 4 |
| | **30** | **60** |

כיתה ח׳:

| נושא | קיים | להוסיף |
|---|---|---|
| ביטויים אלגבריים | 3 · 1 · 1 | 2 · 4 · 4 |
| משוואות | 3 · 3 · 2 | 2 · 2 · 3 |
| חזקות ושורשים | 3 · 2 · 2 | 2 · 3 · 3 |
| משפט פיתגורס | 1 · 1 · 1 | 4 · 4 · 4 |
| פונקציה קווית | 0 · 2 · 2 | 5 · 3 · 3 |
| בעיות מילוליות | 0 · 1 · 2 | 5 · 4 · 3 |
| | **30** | **60** |

**סה״כ 120 שאלות חדשות**, לא 180.

שימו לב ששלושה תאים ריקים לגמרי (`יחס ופרופורציה·קל`, `פונקציה קווית·קל`,
`בעיות מילוליות·קל`) — שם אין דוגמה קיימת להישען עליה, וצריך לקבוע את רמת הפתיחה
של הנושא מאפס.

### מבנה הקבצים

תבנית זהה ל-`grade1.ts`, שהיא כבר מוכחת:

```
import type { Topic } from "./curriculum";
import { level } from "./level";

export const grade6Topics: Topic[] = [
  { id: "fractions", title: "שברים פשוטים",
    levels: [ level("easy", [ ...5 ]), level("medium", [ ...5 ]), level("hard", [ ...5 ]) ] },
  ...
];
```

**`level()` מיובא מ-`./level` ולעולם לא מ-`./curriculum`.** זו לא העדפת סגנון:
`curriculum.ts` מייבא את קבצי הכיתות, ולכן ייבוא הפוך סוגר מעגל שנכשל **בזמן ריצה
בלבד** — מסך לבן עם `Cannot access 'LEVEL_META' before initialization`, ו-TypeScript
לא תופס אותו. זה כבר קרה כאן פעם אחת.

שני קבצים ולא אחד, במקביל ל-`grade1.ts`: כיתה היא יחידת התוכן הטבעית, וקובץ אחד
בן 180 שאלות היה הופך כל עריכה עתידית לחיפוש.

**מזהים:** `g6-<topicId>-<e|m|h><n>`, למשל `g6-fractions-e1` — אותה תבנית
כמו `g1-numbers-e1`. המזהים הקיימים (`g6-e1`) **משתנים** בהתאם; הם אינם נשמרים
ב-localStorage (ההיסטוריה שומרת נושא, רמה וציון בלבד), ולכן השינוי אינו שובר
נתונים קיימים.

### מה כבר עובד ולא דורש נגיעה

- **`שאלה X מתוך Y`** — כבר נגזר מ-`level.questions.length`. נבדק. אין שינוי.
- **`promptSegments`** — כבר מפצל על גרשיים אחוריים ומסמן כל קטע כ-`math` או
  `text`, בדיוק כפי ש-design.md דורש. **אין שינוי נדרש בקוד** — הדרישה כולה נופלת
  על **כתיבת הנתונים**.
- **`isHebrewPrompt`** — מזהה תו עברי כלשהו ומחליט על כיוון הפסקה. עובד כמו שהוא.

## Edge Cases
- **תלות מעגלית** — ראו למעלה. הכשל היחיד כאן שמפיל את האפליקציה לגמרי.
- **ביטוי אלגברי בתוך משפט עברי** — חייב גרשיים אחוריים בנתונים, אחרת
  `3(x + 2)` מוצג `3)2 + x(`. חל על שאלות, שלבים ודימויים.
- **תשובה שאינה מספר שלם** — `answer` הוא מספר; שברים עשרוניים בכיתה ו׳ תקינים
  (`0.8`), אבל שאלה שהתשובה הטבעית לה היא שבר פשוט צריכה ניסוח שמייצר מספר.
  זה כבר הכלל בפרויקט ולא חדש כאן.
- **נקודה עשרונית בהקראה** — `2.5` נשאר יחידת דיבור אחת; טופל בפיצ'ר ההקראה
  ואין צורך בטיפול נוסף, אבל שווה לדעת שהוא נבדק.
- **דימוי כפול** — יש בדיקה שסורקת את כל הדימויים ודורשת ייחודיות. עם 120 חדשים
  זה הופך למלכודת ממשית ולא תיאורטית.
- **`analogy` חסר** — לא מתקמפל. זה מכוון.
- **תא ריק** — אין תא עם פחות מ-5 אחרי השינוי; שלושת התאים הריקים היום מקבלים 5.

## Risks / Tradeoffs
- **זה שינוי תוכן גדול.** 120 שאלות חדשות עם שלבים ודימוי ייחודי כל אחת. הסיכון
  המרכזי אינו טכני אלא **איכות ואחידות** — קל לייצר 120 שאלות בינוניות. הבדיקות
  יתפסו כפילות דימוי וסתירת נושא, אבל **לא** יתפסו שאלה משעממת או דימוי שלא
  מתחבר לילד. זו ביקורת אנושית שנשארת למשתמש.
- **מחיקת האיחוד המבחין מקטינה את רשת הביטחון לעתיד.** אם יום אחד תוחזר כיתה
  ללא נושאים, יהיה צריך להחזיר את האיחוד. זה מקובל: לא נכון לשאת מנגנון לתרחיש
  שאין לו לקוח, ולהחזיר אותו זה בדיוק אותו קומיט הפוך.
- **המזהים משתנים** מ-`g6-e1` ל-`g6-fractions-e1`. נבדק שאינם נשמרים בשום מקום
  מתמשך, כך שאין נתונים שנשברים.
- **`curriculum.ts` מתכווץ משמעותית** (60 שאלות יוצאות ממנו). דיף גדול, אבל
  התוצאה היא קובץ שמגדיר מבנה בלבד — כפי שהיה אמור להיות.

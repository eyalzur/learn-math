# אבחון הטעות ושיחה עליה — Architecture

## Overview
מודול חדש `src/data/diagnose.ts` מחזיק פונקציה טהורה אחת שמקבלת שאלה ותשובה שהוקלדה
ומחזירה אבחנה או `null`. `Practice.tsx` קורא לה ברגע הבדיקה, ומצייר את קופסת השיחה
כשחזרה אבחנה. כשחזר `null` — הרכיב מצייר בדיוק את מה שהוא מצייר היום.

## Affected Files / Components

| קובץ | מה משתנה |
|---|---|
| `src/data/diagnose.ts` | **חדש.** רשימת הדפוסים, כל אחד עם הזיהוי והניסוח שלו, ופונקציית `diagnose`. |
| `src/components/Practice.tsx` | קורא ל-`diagnose` ב-`checkAnswer`; מצב חדש לשיחה; שורת האבחנה במקום שורת "לא נכון"; קופסת השיחה; הסתרת ההסבר עד החשיפה. |
| `src/App.css` | מחלקות לשורת האבחנה ולקופסת השיחה. |
| `src/data/speech.ts` | ללא שינוי בקוד — אבל שני כפתורי הקראה על מסך אחד דורשים מעקב מי מדבר, ראו למטה. |

## Data / State Changes

### טיפוס חדש ב-`diagnose.ts`

```
Diagnosis {
  id        מזהה הדפוס, לבדיקות ולניפוי
  headline  שורת האבחנה — "נראה שקראת `2` במקום `12`"
  question  השאלה הקטנה — "כמה זה `10 + 2`?"
  answer    התשובה לשאלה הקטנה (מספר)
  onRight   תגובה לתשובה נכונה
  onWrong   תגובה לתשובה שגויה
}
```

כל המחרוזות עוברות ב-`promptSegments` בעת ההצגה, ולכן **המספרים בהן מסומנים
בגרשיים אחוריים** — בדיוק כמו הרמזים. זה לא קישוט: "קראת `2` במקום `12`" בלי
בידוד מוצג בסדר הפוך, והמשפט הופך לשקר.

### מצב חדש ב-`Practice.tsx`

| מצב | טיפוס | מתאפס ב-`next()` |
|---|---|---|
| `diagnosis` | `Diagnosis \| null` | ✓ |
| `followUpInput` | `string` | ✓ |
| `followUpResult` | `"right" \| "wrong" \| null` | ✓ |
| `askedToSee` | `boolean` | ✓ |
| `speakingBox` | `"diagnosis" \| "explanation" \| null` | ✓ |

`revealed` **אינו מצב** אלא נגזרת: `followUpResult !== null || askedToSee`. שני
מקורות לאותה עובדה כמצבים נפרדים הם בדיוק איך נוצר מסך שסותר את עצמו.

`speakingBox` מחליף את `isSpeaking` הקיים. שני כפתורי הקראה על מסך אחד מול מנוע
דיבור אחד — דגל בוליאני היה מציג "עצור" על שניהם בזמן שרק אחד מדבר.

**אין שינוי ב-`Question`, ב-`Topic` או ב-`progress.ts`.** הניקוד נסגר לפני שהשיחה
נפתחת, בדיוק כמו היום.

## Technical Approach

### מיקום המודול, והתלות המעגלית
`diagnose.ts` מייבא את `Question` **בתור טיפוס בלבד** (`import type`), ולכן הייבוא
נמחק בקומפילציה ואינו יכול ליצור מעגל בזמן ריצה. בנוסף, **אף קובץ נתונים לא מייבא
את `diagnose`** — הקורא היחיד הוא `Practice.tsx`. זו בדיוק התקלה ש-`level.ts` נולד
בגללה, והפעם היא נמנעת מראש ולא אחרי מסך לבן.

### מבנה: דפוס = זיהוי + ניסוח באותו מקום
כל דפוס הוא רשומה אחת עם פונקציית זיהוי שמחזירה `Diagnosis` או `null`:

```
PATTERNS = [
  { id: "sign",     detect(question, given) → Diagnosis | null },
  { id: "operation",  ... },
  { id: "reversed",   ... },
  { id: "tens",       ... },
  { id: "offByOne",   ... },
]
```

`diagnose` עוברת עליהן **לפי הסדר ומחזירה את הראשונה שתפסה**. הניסוח יושב יחד עם
הזיהוי ולא בטבלה נפרדת, מאותה סיבה שכללי התוכן בנויים כך: דפוס שהזיהוי שלו והמילים
שלו בשני קבצים שונים יתפצל ביניהם בפעם הראשונה שמישהו יערוך רק אחד מהם.

### הסדר הוא ההכרעה, והוא מהספציפי לרחב

| # | דפוס | תופס כאשר | למה במקום הזה |
|---|---|---|---|
| 1 | סימן הפוך | `given === -correct`, ו-`correct ≠ 0` | התאמה מדויקת, אפס מקום לפרשנות |
| 2 | פעולה הפוכה | השאלה היא ביטוי `a OP b`, והתשובה שווה לתוצאת הפעולה ההפוכה | דורש התאמה גם לאופרטור וגם לאופרנדים |
| 3 | היפוך ספרות | `correct ≥ 10`, `given ≥ 10`, אותן ספרות בסדר הפוך | מבני, אבל פחות ספציפי מהתאמת פעולה |
| 4 | התעלמות מהעשרות | בשאלה יש מספר דו-ספרתי, ו-`given` שווה לספרת היחידות שלו | דורש מספר דו-ספרתי בשאלה כדי שאפשר יהיה בכלל לנסח |
| 5 | סטייה של אחד | `\|given − correct\| === 1` | **אחרון תמיד** — ראו למטה |

**דוגמה לעימות אמיתי:** תשובה שהיא גם היפוך ספרות וגם סטייה של אחד. הסדר מכריע
לטובת ההיפוך, כי הוא אומר משהו על מה שנעשה, בעוד "פספסת באחד" נכון גם כשהוא
מקרי.

### למה "סטייה של אחד" אחרון, ולמה בכלל
הוא היחיד שיכול לתפוס תשובה שהיא סתם ניחוש שנפל קרוב. הוא נשאר, כי בספירה סטייה של
אחד היא כמעט תמיד אמיתית — אבל **רק אחרי שכל הדפוסים המבניים לא תפסו**, ולעולם לא
כהסבר לתשובה שיש לה הסבר טוב יותר.

### הכל על שלמים, למעט הסימן
כל הדפוסים דורשים ש-`correct` ו-`given` יהיו **שלמים**, למעט "סימן הפוך" שעובד על
כל מספר. השוואות שברים דורשות סף סובלנות, וסף סובלנות באבחון פירושו אבחנה שנכונה
"בערך" — וזה בדיוק מה שהספק אוסר. שברים אצל רותם פשוט לא יאובחנו.

### חילוץ המספרים לניסוח
"קראת `2` במקום `12`" צריך את **המספר מהשאלה**, לא מהתשובה. הדפוס מחלץ את המספר
הדו-ספרתי הראשון מ-`question.prompt`. **אם אין כזה — הדפוס לא תופס**, גם אם החשבון
מתאים. אי אפשר לנסח אבחנה על מספר שלא הוזכר.

### הזרימה ב-`Practice.tsx`
1. `checkAnswer` על תשובה שגויה קורא ל-`diagnose` ושומר את התוצאה.
2. הרינדור מתפצל: `diagnosis === null` → המסך של היום, אות באות.
3. `diagnosis !== null` ולא נחשף → שורת האבחנה, קופסת השיחה, **בלי** `.explanation`.
4. בדיקת השאלה הקטנה משווה מספרית ומציבה `followUpResult`.
5. `revealed` נגזר → `.feedback.wrong` ו-`.explanation` נכנסים למסך.
6. `next()` מאפס הכל וקורא ל-`stopSpeaking`, כמו היום.

## Edge Cases

- **תשובה זהה לנכונה** לא מגיעה לאבחון בכלל — הענף הוא תחת `wrong`.
- **קלט ריק בשאלה הקטנה** חסום כמו בשדה הראשי (`input.trim() === ""`).
- **`correct === 0`** מוציא את "סימן הפוך" מהמשחק (`-0 === 0`), ולכן נדרש במפורש.
- **`10` מול `1`** אינו נחשב היפוך ספרות: הדפוס דורש `given ≥ 10`, אחרת כל אפס
  מוביל היה הופך למסקנה.
- **`correct % 10 === correct`** (תשובה חד-ספרתית) מוציא את "התעלמות מהעשרות".
- **שני כפתורי הקראה** — `speakingBox` מבטיח שלחיצה על אחד עוצרת את השני ולא
  משאירה שני כפתורי "עצור" על המסך.
- **`type="number"`** בשדה הקטן כדי שתעלה מקלדת מספרים, כמו בשדה הראשי.
- **מעבר לשאלה הבאה באמצע שיחה** — מותר במפורש, ומאפס.

## Risks / Tradeoffs

### מה נשבר בבדיקות הקיימות: כלום, ומסיבה מבנית
`mistake-explanation.spec.ts` ו-`teaching-explanations.spec.ts` עונים תמיד `999999`.
המספר הזה לא תופס באף דפוס — הוא לא נגטיב של התשובה, לא היפוך ספרות שלה, לא ספרת
יחידות, ולא רחוק ממנה באחד. כלומר **הן ממשיכות לרוץ במסלול הלא-מאובחן, שהוא לפי
הספק זהה להיום**, ואין צורך לגעת בהן.

זו לא מזל. זו תוצאה ישירה של ההכרעה "בלי דפוס — המסך של היום": פיצ'ר שמוסיף התנהגות
רק כשהוא בטוח, לא יכול לשבור התנהגות קיימת.

**ל-QA:** כדי להגיע לאבחנה בכיתה א׳ — רמה **בינונית**, שאלה ראשונה: "איזה מספר בא
אחרי `12`?", תשובה נכונה `13`. הקלדת `3` מפעילה בדיוק את המקרה שדווח.

### מה לא נעשה, בכוונה
- **אין ניתוח מלא של הביטוי.** "פעולה הפוכה" מזהה רק `a OP b` פשוט. שאלת מילים
  לא תאובחן כך, וזה מקובל — עדיף לא לתפוס מאשר לתפוס לא נכון.
- **אין למידה מהיסטוריית טעויות.** מחוץ לתחום בספק במפורש.
- **אין אבחון לשברים ולאחוזים** מלבד היפוך סימן, כאמור למעלה.

### הסיכון שנשאר
הדפוס "התעלמות מהעשרות" עלול לתפוס תשובה שבמקרה שווה לספרת היחידות. שני משמרים
מצמצמים את זה — נדרש מספר דו-ספרתי בשאלה, ונדרש שהתשובה שהוקלדה תהיה חד-ספרתית —
אבל הוא אינו נעלם. זה הדפוס שכדאי להסתכל עליו ראשון אם המשתמש ידווח על אבחנה
מוזרה.

## Implementation Notes

נבנה לפי התכנון. שלוש סטיות, וכולן תיקונים לטעויות במסמכים שקדמו:

### 1. הזיהוי של "התעלמות מהעשרות" היה שגוי, והבאג מלמד על הטעות עצמה
התכנון קבע שהתשובה שהוקלדה שווה **לספרת היחידות של המספר בשאלה**. זה לא נכון,
והמקרה שדווח מפריך אותו: "איזה מספר בא אחרי `12`?" נענה `3`, וספרת היחידות של
`12` היא `2`.

הקשר האמיתי: `3` הוא מה שמתקבל מפתרון **נכון** של השאלה על מספר שנקרא **לא נכון**.
כלומר `13` בלי העשרת — כלומר `correct % 10`. אותו יחס עובד גם על `12 + 5` שנענה
`7`, ועל `18 − 4` שנענה `4`.

המשמר על מספר דו-ספרתי בשאלה נשאר, ומרוויח נימוק שני: בלי מספר דו-ספרתי לא היו
עשרות לפספס מלכתחילה. `8 + 5` שנענה `3` הוא טעות אחרת לגמרי, והדפוס שותק לגביה
בצדק.

הבדיקה הראשונה נכשלה בדיוק כאן, לפני שנכתבה עליה בדיקה — הרצתי את המקרה שדווח
מול האפליקציה.

### 2. הקופי של "פעולה הפוכה" לא היה ניתן לענייה
`design.md` נתן את השאלה הקטנה "הסימן כאן הוא חיבור או חיסור?" מול שדה **מספרי**
שאותו מסמך עצמו קובע. הוחלף בתרגיל חיבור או חיסור זעיר שמבודד את אותה אי-הבנה.
`design.md` עודכן ולא רק הקוד.

### 3. ביטוי שנכתב הפוך במסמך
`design.md` כתב את השאלה הקטנה של "סימן הפוך" כ-`2 × 3-`, כלומר כפי שהיא *נראית*
אחרי היפוך RTL. בנתונים היא נכתבת בסדר הלוגי `-3 × 2`, והבידוד מציג אותה נכון.
זו המלכודת המדויקת שחזרה בפרויקט שלוש פעמים, והפעם היא נתפסה במסמך לפני הקוד.

### שאר מה שנבנה
- `segmented()` חולץ כעוזר משותף ב-`Practice.tsx`; רינדור הרמזים עבר להשתמש בו
  במקום להעתיק את אותן שש שורות.
- `diagnosisToSpeechParts` ממיר את הביטויים המסומנים למילים עבריות דרך
  `mathToWords`, כמו שההסבר עושה — אחרת מנוע הדיבור מדלג על החשבון.
- `isSpeaking` הוחלף ב-`speakingBox`. לחיצה על כפתור אחד בזמן שהשני מדבר עוצרת
  אותו ומתחילה את החדש.
- `npm run test:e2e` — 75 בדיקות עוברות, אף אחת לא שונתה. כפי שנחזה: הן עונות
  `999999`, שלא תופס באף דפוס.
- גרסה 1.5.1 → 1.6.0.

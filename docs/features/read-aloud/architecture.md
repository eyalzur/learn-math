# הקראה בקול של ההסבר — Architecture

## Overview
מודול דק מעל `window.speechSynthesis` (Web Speech API), שמובנה בדפדפן ולכן לא דורש
שרת, מפתח או תשלום - בדיוק האילוץ שהוגדר לפרויקט. בתוספת המרת חשבון למילים עברית.

## Affected Files / Components
- **`src/data/speech.ts`** (חדש) — זיהוי יכולת, המרת חשבון למילים, הקראה ועצירה.
- **`src/components/Practice.tsx`** — כפתור ההקראה ועצירה במעבר שאלה.
- **`src/App.css`** — סגנון הכפתור ושורת הכותרת.

## Data / State Changes
אין נתונים מתמשכים. `Practice` מחזיק `isSpeaking: boolean` בלבד, לצורך האייקון.

## Technical Approach
`speechSupported()` בודק `"speechSynthesis" in window`. הכפתור מרונדר רק אם כן, כך
שאין מצב של כפתור שלוחצים עליו ולא קורה כלום.

`mathToWords` מחליף סימנים במילים עבריות עם רווחים סביבם. ההמרה חלה על שדה ה-`math`
של כל שלב בלבד - שדה הטקסט הוא כבר עברית תקינה.

`speakExplanation` מרכיב מחרוזת אחת מכל השלבים ומהדימוי, מופרדים בנקודה כדי לקבל
הפסקה טבעית, ומשמיע אותה כ-utterance יחיד. utterance אחד ולא רבים כדי שעצירה תהיה
מיידית ולא תמתין לסיום הפריט הנוכחי בתור.

בחירת קול: `getVoices()` ומחפשים קול ש-`lang` שלו מתחיל ב-`he`. הרשימה נטענת
אסינכרונית בחלק מהדפדפנים, ולכן יש גם מאזין ל-`voiceschanged`. אם אין קול עברי,
עדיין מוגדר `utterance.lang = "he-IL"` ונותנים לדפדפן לבחור - הקראה בקול לא אידיאלי
עדיפה על שתיקה.

## Edge Cases
- **אין `speechSynthesis`** — הכפתור לא מרונדר.
- **אין קול עברי במכשיר** — נופל לברירת המחדל של הדפדפן.
- **קולות נטענים מאוחר** — מאזין `voiceschanged`.
- **מעבר שאלה בזמן הקראה** — `cancel()` ב-`next()`, אחרת ההסבר של השאלה הקודמת
  ממשיך להישמע מעל השאלה החדשה.
- **יציאה מהתרגול בזמן הקראה** — אותו טיפול ב-`onExit`.
- **לחיצה כפולה מהירה** — `cancel()` לפני כל `speak()`.

## Risks / Tradeoffs
- איכות ההקראה משתנה בין מכשירים ואינה בשליטתנו. זה המחיר של פתרון בלי שירות בתשלום,
  והחלופה - הקלטות קול מראש ל-240 שאלות - אינה מציאותית ולא תעבוד על תוכן חדש.
- `speechSynthesis` הוא API גלובלי עם מצב משלו; לכן כל הגישה אליו מרוכזת במודול אחד
  במקום להתפזר בקומפוננטות.

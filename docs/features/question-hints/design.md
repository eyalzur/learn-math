# שני רמזים לכל שאלה — Design

## Overview
כפתור `רמז` מתחת לשדה התשובה. לחיצה חושפת את הרמז הראשון, לחיצה נוספת את השני,
ואז הכפתור נעלם. הרמזים נשארים על המסך עד השאלה הבאה.

## Screens / States

### לפני שמבקשים — המצב הרגיל
```
┌────────────────────────────────────┐
│  ← חזרה              שאלה 3 מתוך 10│
│                                    │
│           8 + 5  =  [    ]         │
│                                    │
│              [ בדיקה ]             │
│                                    │
│              רמז 💡                │   ← חדש, קטן ומשני
└────────────────────────────────────┘
```

### אחרי לחיצה אחת
```
│              [ בדיקה ]             │
│                                    │
│  ┌──────────────────────────────┐  │
│  │ קודם משלימים לעשר, ואז       │  │
│  │ מוסיפים את מה שנשאר          │  │
│  └──────────────────────────────┘  │
│                                    │
│              עוד רמז 💡            │
```

### אחרי לחיצה שנייה — המצב הסופי
```
│  ┌──────────────────────────────┐  │
│  │ קודם משלימים לעשר, ואז       │  │
│  │ מוסיפים את מה שנשאר          │  │
│  ├──────────────────────────────┤  │
│  │ כמה זה 8 + 2? ואם זה 10,     │  │
│  │ כמה נשאר להוסיף מתוך ה-5?    │  │
│  └──────────────────────────────┘  │
```
**אין כפתור.** אין רמז שלישי, ולכן אין מה להציע.

### מצבים נוספים
- **אחרי בדיקת תשובה** — הכפתור נעלם. הרמזים שכבר נחשפו **נשארים**: הם חלק ממה
  שקרה בשאלה הזו, ולהעלים אותם ברגע שמופיע ההסבר זו מחיקה של המאמץ.
- **שאלה בלי רמזים כתובים** — הכפתור לא מרונדר כלל. 300 השאלות שעוד לא קיבלו
  רמזים ייראו בדיוק כמו היום.

## Copy

| מחרוזת | מתי |
|---|---|
| `רמז 💡` | כשעוד לא נחשף אף רמז |
| `עוד רמז 💡` | אחרי הרמז הראשון |

**`רמז` ולא `עזרה`.** רמז זה משהו שלוקחים כדי להצליח לבד; עזרה זה משהו שמקבלים
כשלא מצליחים. ההבדל הזה נשמע דק למבוגר ולא דק בכלל לילדה בת שבע.

**`עוד רמז` ולא `רמז 2`.** מספור הופך את זה למשאב שסופרים, ומי שסופר מתחיל
להסס לפני שהוא לוקח.

אין טקסט "נשארו לך רמזים", אין מונה, ואין הודעה כשנגמרו — הכפתור פשוט נעלם.

## Interaction Flow
1. השאלה מוצגת. מתחת ל"בדיקה" יש `רמז 💡`, קטן ומשני.
2. לחיצה → הרמז הראשון מופיע מעליו, והכפתור הופך ל`עוד רמז 💡`.
3. לחיצה נוספת → הרמז השני מופיע מתחת לראשון, והכפתור נעלם.
4. שני הרמזים נשארים גלויים בזמן שמקלידים ובודקים.
5. מעבר לשאלה הבאה → הכל מתאפס; שוב `רמז 💡` ואף רמז לא מוצג.

**הרמזים לא נעלמים כשמופיע ההסבר.** הם נשארים בתחתית המסך גם אחרי הבדיקה. זה
מכוון — הפער בין "מה ניסיתי" ל"מה היה צריך" הוא בדיוק מה שמלמד.

**סדר האלמנטים, ולמה:** הרמזים והכפתור יושבים **מתחת לשורת הכפתורים**, ישירות
זה מעל זה. הסקיצות למעלה מתארות את המצב שבו הרמזים בשימוש בפועל — לפני שעונים —
ושם זה הסדר הנכון: השאלה, `בדיקה`, ואז הרמזים והכפתור.

נוסח קודם של המסמך הזה אמר שאחרי טעות הרמזים יופיעו **מעל** ההסבר. זה סותר את
הסדר שלמעלה: אי אפשר שאותו אלמנט יהיה גם מתחת ל`בדיקה` וגם מעל ההסבר, שיושב
מעליה. הוכרע לטובת המצב הנפוץ — הרמזים נשארים למטה תמיד, וההסבר מופיע במקומו
הרגיל. אחרי טעות הקריאה היא: "לא נכון" ← ההסבר ← `הבא` ← הרמזים שנלקחו.

## Accessibility / RTL notes
- **הרמז השני מכיל תרגיל חשבוני בתוך משפט עברי** (`כמה זה 8 + 2?`). זה בדיוק
  הצירוף ששבר את הפרויקט שלוש פעמים. הביטוי חייב להיות **מסומן בגרשיים אחוריים
  בנתונים** ולרונדר כאלמנט מבודד משלו, כמו בשאלות עצמן. מי שכותב רמז ושוכח -
  מייצר את הבאג מחדש.
- **הרמז הראשון בדרך כלל נטול מספרים** ולכן אין לו בעיית כיוון. אם יוזכר בו
  מספר (`עד 10`) — אותו כלל חל.
- הכפתור **חייב טקסט ולא רק אייקון**. הוא לא מובן מעצמו כמו רמקול, ואינו נסמך
  על ניסיון קודם.
- האמוג׳י 💡 הוא קישוט לצד המילה, לא תחליף לה. אין לו משמעות שאובדת בקורא מסך.
- **הרמזים מופיעים מתחת לכפתור הבדיקה ולא מעל השאלה**, כדי שהשאלה תישאר במקום
  שהעין כבר מכירה. תוספת שמזיזה את השאלה כלפי מעלה תגרום לחיפוש מחדש בכל לחיצה.

## Acceptance Criteria Check
- "אפשר לבקש רמז לפני בדיקה": **כן** — הכפתור מתחת ל"בדיקה".
- "הרמז אינו מוצג מעצמו": **כן** — זרימה 1, אין רמז על המסך עד לחיצה.
- "ראשון שיטתי, שני בבקשה נוספת": **כן** — זרימה 2-3.
- "אין רמז שלישי ואין אפשרות לבקש עוד": **כן** — הכפתור נעלם.
- "הרמזים נשארים גלויים": **כן** — זרימה 4, וגם אחרי הבדיקה.
- "מעבר לשאלה מתחיל מחדש": **כן** — זרימה 5.
- "בקשת רמז אינה משנה ניקוד": **לא עניין עיצובי** — אין שום ייצוג של ניקוד
  בכפתור או ליד הרמזים, וזה מכוון: מונה או אזהרה היו הופכים בקשת רמז למחיר.
- "אחרי בדיקה אי אפשר לבקש עוד": **כן** — הכפתור נעלם.
- "שאלה בלי רמזים לא מציגה כפתור": **כן** — מצב רביעי.
- קריטריוני התוכן: **לא עניין עיצובי.**

# הודעת עידוד לציון מושלם — Architecture

## Overview
שינוי לוגי קטן בתוך `Result.tsx`: הוספת תנאי נוסף למחרוזת ה-`message` הקיימת שכבר
מחושבת מ-`percent`. אין צורך בקומפוננטה חדשה, state חדש, או תלות חדשה.

## Affected Files / Components
- `src/components/Result.tsx` — עדכון לוגיקת בחירת ה-`message` כך שתבדיל בין
  `80 ≤ percent < 100` (ההודעה הקיימת) לבין `percent === 100` (ההודעה החדשה).

## Data / State Changes
אין. `percent` ו-`correctCount`/`total` כבר מחושבים בקומפוננטה הקיימת; הפיצ'ר רק
מוסיף ענף נוסף ל-if/else הקיים ולא דורש state, props, או טיפוסים חדשים.

## Technical Approach
להחליף את שרשרת ה-`if/else if/else` הנוכחית (3 ענפים) בשרשרת עם 4 ענפים, כשהענף
האחרון בודק `percent === 100` באופן מפורש ומחזיר את המחרוזת החדשה, והענף שלפניו
(`80 ≤ percent < 100`) נשאר עם ההודעה הקיימת. הבדיקה `percent === 100` צריכה לבוא
*אחרי* הבדיקה `percent < 80`, כלומר לפני ה-`else` הסופי, כדי לשמור על סדר הבדיקות
הקיים ולא לשבור את שלושת המקרים האחרים.

## Edge Cases
- `total === 0` (סט תרגילים ריק): לא רלוונטי בפועל — כל הסטים הקיימים ב-
  `src/data/exerciseSets.ts` מכילים 10 תרגילים, ואין דרך במשק כיום ליצור סט ריק.
  לא נדרש טיפול מיוחד.
- `percent` מחושב עם `Math.round`, כך ש-100% מתקבל רק כאשר `correctCount === total`
  בפועל (למשל 9/10 = 90%, לא מתעגל ל-100%) — אין סיכון של "כמעט מושלם" שמוצג בטעות
  כמושלם.
- אין באג RTL/LTR חדש כאן — ראו הערת Accessibility/RTL ב-design.md.

## Risks / Tradeoffs
שינוי מינימלי וממוקד; אין טרייד-אוף משמעותי. נבחר לא להוציא את מיפוי
האחוז-להודעה לפונקציה/קובץ נפרד (כמו `answerOf` ב-`exerciseSets.ts`) כי הלוגיקה
עדיין קצרה ומקומית ל-`Result.tsx` בלבד — אם יתווספו עוד רמות הודעה בעתיד, יהיה
כדאי לשקול חילוץ כזה מחדש.

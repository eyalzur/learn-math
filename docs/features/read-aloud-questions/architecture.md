# הקראת השאלה — Architecture

## Overview
מודול העדפות חדש ליד `progress.ts` שומר לכל תלמיד/ה דגל אחד ב-localStorage.
`TopicPicker` מציג מתג שכותב אליו, ו-`Practice` קורא אותו ומפעיל הקראה כשמופיעה
שאלה או נפתח רמז — דרך אותו מנגנון דיבור שההסבר משתמש בו כבר.

## Affected Files / Components

| קובץ | מה משתנה |
|---|---|
| `src/data/preferences.ts` | **חדש.** קריאה וכתיבה של ההעדפה לפי `studentId`. |
| `src/data/speech.ts` | `speechParts()` **חדשה** — ממירה מחרוזת עם ביטויים מסומנים לחלקי דיבור. מאחדת כפילות קיימת. |
| `src/components/TopicPicker.tsx` | קופסת המתג בראש המסך, מוצגת רק כשיש מנוע דיבור. |
| `src/components/Practice.tsx` | כפתור מעל קופסת השאלה; `speakingBox` מתרחב; הקראה אוטומטית לשאלה ולרמז. |
| `src/App.tsx` | מעביר `studentId` ל-`TopicPicker` ואת ההעדפה ל-`Practice`. |
| `src/App.css` | קופסת המתג וכפתור השאלה. |

## Data / State Changes

### `preferences.ts` — למה לא בתוך `progress.ts`
`progress.ts` הוא **יומן**: רשומות שנצברות, נקראות לפי תלמיד/ה, ולעולם לא מתעדכנות.
העדפה היא ההפך — ערך יחיד שנדרס. לדחוף אותה לאותו מערך היה מכריח כל קריאת
היסטוריה לסנן החוצה שורות שאינן תרגולים, וזה בדיוק סוג הערבוב שנראה זול ביום
הראשון ויקר אחר כך. **קובץ נפרד, מפתח `learn-math:preferences` נפרד.**

```
readAloud(studentId) → boolean          ברירת מחדל false
setReadAloud(studentId, value) → void
```

אותו משמר כמו ב-`progress.ts`: כל גישה ל-localStorage עטופה ב-`try`, ובכישלון
מוחזר `false`. מצב פרטי בדפדפן זורק, ואובדן העדפה אינו סיבה להפיל תרגול.

### `speech.ts` — `speechParts()` מאחדת כפילות שכבר נוצרה
בענף הזה קיימת `diagnosisToSpeechParts` ב-`Practice.tsx` שממירה מחרוזת עם גרשיים
אחוריים לדיבור. השאלה והרמזים צריכים **בדיוק את אותו דבר**. שלוש העתקות של אותה
לוגיקה הן שלושה מקומות שיתפצלו.

```
speechParts(texts: string[]) → string[]
```

ממירה כל ריצת חשבון מסומנת דרך `mathToWords`, מנקה רווחים, ומשליכה ריקים.
`diagnosisToSpeechParts` נמחקת וקוראיה עוברים אליה. היא יושבת ב-`speech.ts` כי
היא על **דיבור**, לא על המסך.

### מצב ב-`Practice.tsx`

`speakingBox` מתרחב ל-`"question" | "diagnosis" | "explanation" | null`. זו הסיבה
שהוא נבנה כאיחוד מבחין ולא כבוליאני — הוספת דובר שלישי היא הוספת ערך אחד.

**אין מצב חדש להעדפה** — היא מגיעה כ-prop מ-`App`.

### props
- `TopicPicker` מקבל `studentId?: string` ומציג את המתג רק כשהוא קיים ויש דיבור.
- `Practice` מקבל `readAloud: boolean`.

## Technical Approach

### ההקראה האוטומטית: אפקט שתלוי בשאלה, לא בכל רינדור
`useEffect` שתלוי ב-`question.id` וב-`readAloud`. כשהשאלה משתנה וההעדפה דלוקה —
עצירה של מה שרץ, ואז הקראה של השאלה. התלות ב-`question.id` ולא באובייקט מונעת
הקראה חוזרת בכל רינדור, וכל הקלדה בשדה התשובה היא רינדור.

**הרמז** מקבל אפקט משלו שתלוי ב-`hintsShown`: כשהמספר עולה וההעדפה דלוקה, הרמז
החדש בלבד מוקרא — לא כל הרמזים מהתחלה.

### הביטול כבר פתור, ואין צורך להמציא אותו מחדש
`stopSpeaking()` מקדם `sequenceId` ומבטל טיימר ממתין, ולכן רצף ישן שכבר התחיל אינו
ממשיך אחרי מעבר לשאלה הבאה. `next()` כבר קורא לו. מה שנוסף: **גם `checkAnswer`
צריך לעצור**, כי לפי העיצוב לחיצה על "בדיקה" משתיקה הקראה שרצה.

### מה מוקרא
- **השאלה:** `promptSegments(question.prompt)` — קטעי טקסט כמו שהם, קטעי חשבון דרך
  `mathToWords`. שאלה שהיא ביטוי חשוף (`12 + 5`) מומרת כולה.
- **רמז:** דרך `speechParts` על מחרוזת הרמז.
- לחיצה על כפתור השאלה מקריאה את השאלה **ואת הרמזים שכבר נפתחו**, בסדר הזה.

### חסימת קול אוטומטי
עד שהשאלה הראשונה מופיעה כבר בוצעו שלוש לחיצות (תלמיד → נושא → רמה), ולכן
הדפדפן ראה מחווה ו-`speechSynthesis` מותר. אם בכל זאת נחסם — **הכפתור עדיין
עובד**, כי הוא אינו תלוי בהעדפה. אין קוד מיוחד לזה, וזו הנקודה: הכישלון היחיד
האפשרי הוא ששקט יישאר שקט, ולא שמשהו יישבר.

## Edge Cases

- **localStorage זורק** → `false`, כלומר ההתנהגות של היום. אין קריסה.
- **מעבר שאלה תוך כדי הקראה** → `stopSpeaking` לפני התחלת החדשה.
- **"בדיקה" תוך כדי הקראה** → עצירה, לפי העיצוב.
- **יציאה מהתרגול** → כבר מטופל ב-`useEffect(() => stopSpeaking, [])`.
- **לחיצה על כפתור אחד בזמן שאחר מדבר** → המנגנון שכבר קיים: עצירה ואז החדש.
- **דפדפן בלי מנוע דיבור** → אין כפתור, אין מתג, אין קופסה במסך הנושאים.
- **שאלה בלי רמזים** → כפתור השאלה מקריא רק אותה.
- **הקראה אוטומטית והעדפה שנכבית באמצע** → האפקט לא מפעיל שוב; מה שרץ ממשיך עד
  שנעצר ידנית או במעבר. לעצור באמצע משפט כי מישהו שינה הגדרה במסך אחר הוא גרוע
  יותר, וזה ממילא לא יכול לקרות מאותו מסך.

## Risks / Tradeoffs

### מה נשבר בבדיקות: אחת, והיא צריכה להשתנות
- **עשר הבדיקות שמאתרות "הקריאו לי את ההסבר" — לא מושפעות.** התווית ההיא לא
  משתנה, וכפתור ההסבר נשאר במקומו. כפתור השאלה נושא תווית אחרת.
- **`a browser with no speech engine shows no button at all` (שורה 354) — מושפעת
  ומצפה ל-0 כפתורי `.speak-button`.** היא עדיין נכונה: בלי מנוע דיבור גם הכפתור
  החדש לא מוצג. אבל היא מגיעה למסך אחרי טעות, ולכן שווה לוודא שהיא נשארת ירוקה
  ולא רק להניח.
- ברירת המחדל הכבויה שומרת על כל שאר הבדיקות: מי שלא מדליק את המתג רואה בדיוק את
  המסך של היום, ואף בדיקה קיימת לא מדליקה אותו.

### מה לא נעשה
- **אין הקראה של מסכי הבחירה** — מחוץ לתחום בספק.
- **אין בחירת קול או קצב** — הוכרעו בפיצ'ר ההקראה הקודם.
- **אין הקראה אוטומטית של ההסבר** — מחוץ לתחום, ומכוון: קול שמתחיל מעצמו בדיוק
  כשילדה מעכלת טעות הוא הפוך מהמטרה.

### הסיכון שנשאר
הקראה אוטומטית של רמז מסתמכת על כך ש-`hintsShown` עולה רק בלחיצה. אם ייווצר בעתיד
מסלול אחר שמשנה אותו, הרמז יוקרא בלי שביקשו. זה המקום להסתכל בו אם יופיע קול לא
צפוי.

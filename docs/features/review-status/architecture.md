# סטטוס ריוויו — Architecture

## Overview
שדה `reviewed: boolean` על `Topic`, כרטיס `disabled` ב-`TopicPicker`, ושורת הסבר
כשאף נושא בכיתה אינו בדוק.

## Affected Files / Components
- **`src/data/curriculum.ts`** — `Topic` מקבל `reviewed: boolean`.
- **`src/data/grade1.ts`** — חמשת הנושאים: `reviewed: true`.
- **`src/data/grade6.ts`, `src/data/grade8.ts`** — שנים-עשר הנושאים:
  `reviewed: false`.
- **`src/components/TopicPicker.tsx`** — `disabled`, התווית, ושורת ההסבר.
- **`src/App.css`** — `.topic-card:disabled`, `.topic-soon`, `.topics-notice`.
- **`package.json`** — `bump:feature`.

## Data / State Changes

**`reviewed: boolean` — חובה ולא אופציונלי.** זו הנקודה המרכזית בארכיטקטורה הזו.

שדה אופציונלי היה אומר ש**שכחה נחשבת לאישור**: מי שמוסיף נושא חדש ולא חושב על
הסטטוס מקבל `undefined`, וכל טיפול סביר יפרש את זה כ"מוצג רגיל". כלומר תוכן חדש —
בדיוק התוכן שהכי צריך בדיקה — היה נפתח לילדים בשקט.

שדה חובה הופך את זה להפוך: **הקומפיילר מסרב לנושא בלי הכרעה**. אותו שיקול בדיוק
שהפך את `analogy` לחובה.

אין state חדש ב-React ואין שמירה ב-localStorage. `reviewed` הוא נתון סטטי שמשתנה
רק בקומיט.

## Technical Approach

`TopicPicker` מקבל את הנושאים כמו היום. לכל כרטיס:
- `disabled={!topic.reviewed}` — **התכונה האמיתית**, לא רק מחלקת CSS. זה מה שמוציא
  אותו ממסלול ה-Tab ומכריז עליו כלא-זמין לקורא מסך, ומונע את ה-`onClick` בלי
  לסמוך על בדיקה בתוך המטפל.
- תווית `בקרוב` מרונדרת רק כאשר `!topic.reviewed`.

שורת ההסבר מרונדרת כאשר **אף** נושא אינו בדוק. התנאי נגזר מהרשימה שהקומפוננטה
כבר קיבלה — אין צורך במידע נוסף ואין קריאה לנתונים.

**סדר במסך:** ההסבר מעל הגריד, כפי שהעיצוב מראה.

## Edge Cases
- **כל הנושאים בדוקים** — שום שינוי מהיום; אין תווית ואין הודעה.
- **כל הנושאים חסומים** — ההודעה מופיעה, הכרטיסים נשארים מוצגים ומעומעמים.
  זה המצב של רותם ועומר מיד עם המיזוג.
- **נושא חסום שיש לו היסטוריה** — ההיסטוריה נשמרת ב-`localStorage` לפי שם נושא
  ואינה תלויה ב-`reviewed`. מסך ההיסטוריה **לא נוגע** בשדה ולכן ממשיך להציג
  הכל. אומת שאין שם סינון.
- **לחיצה במקלדת על כרטיס חסום** — `disabled` מונע. זו הסיבה שהוא לא רק מעומעם.
- **כיתה בלי נושאים כלל** — לא קיים בפרויקט; לכל כיתה יש נושאים.

## Risks / Tradeoffs
- **הפיצ'ר חוסם תוכן שכבר עובד.** רותם ועומר ייחסמו במלואם. זה מכוון ומתועד
  ב-product-spec, אבל זה המחיר האמיתי ולא הערת שוליים.
- **`reviewed` חובה מכריח לגעת בכל הנושאים הקיימים** — 17 שינויים קטנים. זה
  בדיוק מה שרוצים: כל אחד מהם הוא הכרעה מפורשת ולא ברירת מחדל.
- **הסטטוס גס בכוונה.** נושא שנבדק ואז שונו בו שתי שאלות נשאר "בדוק". ריוויו
  ברמת שאלה היה מדויק יותר וגם היה הופך כל עריכה לפעולה בירוקרטית. הגסות היא
  ההחלטה, לא פשרה.

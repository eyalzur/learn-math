## 1. בשורה אחת

תיקייה אחת של קבצי markdown קטנים (`kb/`). **קובץ אחד = מושג אחד.** שתי פקודות:
`/kb-add` (להוסיף ידע) ו-`/kb-ask` (לשאול). שתיהן רצות דרך סוכן קטן וזול, וסקריפטים
רגילים (בלי LLM) עושים את כל העבודה המכנית — אינדקסים, בדיקת כפילויות, בדיקת קישורים.

## 2. למה OKF

מה שהמאמר של גוגל מגדיר (המאמר מציג v0.1; המפרט בפועל כבר v0.2 — כך בנינו):

- תיקייה של קבצי `.md`. **הנתיב של הקובץ הוא הזהות של המושג.**
- בראש כל קובץ כותרת YAML (`type` חובה; `title`, `description`, `tags`, `timestamp`, `resource` אופציונליים). אחריה גוף חופשי ב-markdown.
- קישורים רגילים בין קבצים יוצרים גרף. `index.md` בכל תיקייה = "תפריט". `log.md` = היסטוריית שינויים.
- אין SDK, אין שרת. עובד על git, על דיסק, על tarball.

למה זה מתאים לנו: זה כבר הדרך שבה הפרויקט עובד (`CLAUDE.md`, `docs/features/`) — רק
מסודר, עם כללים, ואחד לכל אפליקציה.

> ⚠️ המאמר לא מגדיר שפת שאילתות, כפילויות או גרסאות. **את זה אנחנו מוסיפים** (סעיפים 5–6).
> **שלב 0 בוצע:** קראתי את המפרט המלא (v0.2). שינויים מול המאמר: `timestamp` הוחלף ב-`generated.at`; במקום `# Citations` יש `sources`; קישורים מומלצים כנתיב מוחלט מהשורש (`/traps/x.md`); ל-`index.md` אין frontmatter (חוץ מ-`okf_version` בשורש); `log.md` מקובץ לפי תאריך. הכל מיושם.

## 4. איך נראה קובץ

```markdown
---
type: trap
title: כיווניות (RTL) בחשבון
description: חשבון חייב להיקרא שמאל-ימין גם בתוך עמוד עברי. נשבר 3 פעמים.
tags: [rtl, bidi, math]
aliases: [bidi, כיווניות, הפוך]
source: CLAUDE.md#כיווניות
source_hash: 9f3a1c
generated: {by: "human:eyal", at: "2026-11-25T00:00:00Z"}
---
# הכלל
טקסט עברי וביטוי חשבוני הם תמיד שני אלמנטים נפרדים.
# שלוש הפעמים
1. ... 2. ... 3. ...
# ראו גם
[הבדיקות](../topics/rtl-tests.md) · [תלות מעגלית](circular-imports.md)
```

כללי גודל: **עד ~300 שורות / ~1.5K טוקנים לקובץ.** גדל מזה — מפצלים.
שורת `description` אחת, תמיד — היא מה שהסוכן קורא כדי להחליט אם לפתוח את הקובץ.

## 5. הוספת ידע (`/kb-add`) — מהר וללא כפילויות

סוכן `kb-ingest` (מודל קטן). חמישה צעדים:

1. **מסווגים** — איזה `type` ואיזה slug קנוני (`topics/grade6-decimals`).
2. **מחפשים קודם** — `kb-search` (סקריפט) על כותרות, `aliases` ו-`tags`. לא קוראים את כל ה-KB.
3. **מחליטים** — יש מושג קיים → **מעדכנים אותו**. אין → יוצרים. אותו עניין בדיוק → מדלגים.
4. **כותבים** — קובץ אחד (או כמה). עובדה שכבר נמצאת במקום אחר → קישור, לא העתק.
5. **סקריפט** מעדכן `index.md`, `log.md` ובודק (סעיף 7). נכשל → הסוכן מתקן.

**למה אין כפילויות:**

| מנגנון | מה הוא עושה |
|---|---|
| נתיב = זהות | אותו מושג = אותו קובץ. אי אפשר ליצור "עוד אחד" |
| חיפוש לפני כתיבה | שלב 2 חובה; הסקריפט דוחה קובץ חדש שדומה מדי לקיים |
| `aliases` | "RTL", "כיווניות", "bidi" מובילים לאותו קובץ |
| `source_hash` | אותו מקור, בלי שינוי → מדלגים בלי לקרוא שוב |
| עובדה במקום אחד | כל השאר מקשרים. (דוגמה קיימת: סעיף "מה פתוח" ב-`CLAUDE.md` מועתק ידנית בכמה מקומות — כאן זה לא יקרה) |
| סריקת כפילויות שבועית | `kb-lint --dupes` מדווח על קבצים דומים → מאחדים |

## 6. שאילתה (`/kb-ask`) — זולה בטוקנים

עיקרון: **לא טוענים את ה-KB. מנווטים בו** (progressive disclosure).

```
שאלה → index.md ראשי (~1K טוקנים)
     → kb-search על description/aliases/tags (סקריפט, 0 טוקנים)
     → פותחים 1–3 קבצים בלבד
     → תשובה + רשימת הקבצים שנקראו
```

- סוכן `kb-query` במודל קטן, **תקרה קשיחה: עד 3 קבצים ו-~4K טוקנים** לשאלה.
  צריך יותר → אומר "לא מצאתי", לא קורא הכל.
- התשובה תמיד מצטטת נתיבים — אפשר לבדוק.
- חיפוש מנורמל לעברית (אותיות סופיות: `בלון`/`בלונים` — מלכודת שכבר ידועה אצלנו).
- אם הסוכן לא מצא תשובה → רושם את השאלה ב-`kb/_gaps.md` (כך רואים מה חסר).

## 7. סקריפטים (בלי LLM, חינמיים)

`kb/tools/` — Node, פקודה אחת לכל דבר:

| פקודה | תפקיד |
|---|---|
| `kb-index` | בונה מחדש את כל `index.md` מה-frontmatter |
| `kb-search "טקסט"` | מחזיר נתיבים + description, מדורג |
| `kb-lint` | כותרת תקינה · קישורים לא שבורים · גודל · slug ייחודי |
| `kb-lint --dupes` | קבצים דומים (חפיפת כותרת/aliases/טקסט) |
| `kb-stale` | קבצים שה-`source_hash` שלהם השתנה במקור |

`kb-lint` רץ ב-CI — PR עם KB שבור לא ממוזג.

## 8. שימוש חוזר בכל אפליקציה

- **הפורמט אגנוסטי:** כל אפליקציה = תיקיית `kb/` משלה. אין שום דבר של learn-math בכלים.
- **ריפו תבנית אחד** (`kb-kit`): `tools/`, שני הסוכנים, שני ה-skills, והמבנה הריק. אפליקציה חדשה = העתקה אחת.
- **רק הטיפוסים משתנים לפי אפליקציה** — קובץ `kb/_types.md` מגדיר אילו `type` מותרים.
- בהמשך (לא עכשיו): bundle משותף `_shared/` למלכודות כלליות (RTL, GitHub Pages) שחוזרות בכל אפליקציה.

## 10. איך נדע שזה עובד

- שאלה רגילה נענית ב-**≤3 קבצים ו-≤4K טוקנים**.
- הוספת ידע שכבר קיים **לא יוצרת קובץ חדש** (בדיקה אוטומטית: מזינים אותו מקור פעמיים).
- `kb-lint --dupes` על ה-KB המלא: **0** זוגות דומים.
- `CLAUDE.md` קטן: **1,328 ← ~400 מילים** (תוקן: בצ'אט אמרתי בטעות 12 אלף). התוכן המלא נשאר נגיש דרך `/kb-ask`.

## 11. החלטות שקיבלתי בשבילך (תגיד אם לא)

1. **KB בתוך הריפו (`kb/`)**, לא במסד נתונים. זה git, אפשר לראות הכל ב-diff.
2. **בלי וקטורים/embeddings בשלב ראשון.** אינדקסים + חיפוש טקסט מספיקים ל-100 קבצים. נחזור לזה רק אם ה-`_gaps.md` יראה שהחיפוש מחמיץ.
3. **KB הוא ידע לפיתוח (לי ולך), לא חלק מהאפליקציה בדפדפן.** האתר נשאר סטטי.
4. **שפה:** התוכן בעברית, slug-ים ושמות שדות באנגלית.
5. **`docs/features/` נשאר** כיומן עבודה; ה-KB מחזיק את התוצאה ("מה נכון היום"), לא את הסיפור.

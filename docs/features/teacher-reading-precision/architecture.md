# דיוק בתיאור טעות התהליך + גיוון דימוי במשוואות חיבוריות — Architecture

## Overview
שינוי תוכן בשני מקומות שאינם קשורים טכנית זה לזה: (1) תוספת ניסוח לפרומפט
המערכת של השרת (`server/src/readPage.ts`) שמלמדת את המודל מתי להשתמש ברגיסטר
הספציפי לחישוב-אריתמטי-ניתן-לאימות, בלי שינוי סכימה; (2) שני מאגרי-דימויים
חדשים ב-`src/data/adaptiveEquations.ts`, נבחרים דרך `pick()` הקיים.

## Affected Files / Components
- **`server/src/readPage.ts`** — `teacherSystemPrompt()` (שורות 32-48): תוספת
  ניסוח בסעיף 2 של ההוראות (`errorPointer`), ללא שינוי בחתימת הפונקציה או
  בשאר הפרומפט (סעיף 1 `processReflection`, סעיף 3 `finalAnswer`, פסקת

  התלמיד/ה לא צריך/ה לדעת שיש שני רגיסטרים, רק לקרוא משפט אחד ברור).
- **`src/data/adaptiveEquations.ts`** — `additiveEquation()` (שורות 28-51):
  שתי מחרוזות-תבנית בודדות (שורות 47-48) מוחלפות בשני מאגרים חדשים (קבועים

  `additiveEquation`, ב-`makeQuestion()` (שורות 16-25), או בכל פונקציה אחרת
  בקובץ (`multiplicativeEquation` ואילך).
- **`docs/features/notebook-default-practice/architecture.md`** — ציטוט
  הפרומפט שם (סעיף "פרומפט המערכת") יצא-מעודכן אחרי השינוי הזה; **לא נוגעים
  בו כחלק מהפיצ'ר הזה** (תיעוד של פיצ'ר אחר, כבר מוזג) — זה נרשם כאן רק כדי
  ש-developer לא יחשוב שזו רשימת קבצים חסרה.

## Technical Approach

### 1 — תוספת לפרומפט (`server/src/readPage.ts`)
השורה הקיימת (שורה 44):
```
2. errorPointer — רק אם אתם רואים שלב בתהליך הכתוב שאינו עקבי עם השלב שלפניו (למשל: שורה לא נובעת חשבונית מהשורה הקודמת, פעולה שהוחסרה) — משפט קצר שמצביע איפה זה קרה, לא מה התוצאה הנכונה הייתה צריכה להיות. אם התהליך עקבי מתחילתו ועד סופו — השמיטו שדה זה לגמרי, אל תמציאו טעות.
```
מתרחבת לכלול משפט-המשך שמלמד את ההבחנה בין שני הרגיסטרים, **באותו סעיף 2**
(לא סעיף נפרד, כי זה עדיין אותו שדה `errorPointer` יחיד — רק הנחיה לניסוח
שלו, לא מבנה נתונים נוסף):

```
2. errorPointer — רק אם אתם רואים שלב בתהליך הכתוב שאינו עקבי עם השלב שלפניו (למשל: שורה לא נובעת חשבונית מהשורה הקודמת, פעולה שהוחסרה) — משפט קצר שמצביע איפה זה קרה, לא מה התוצאה הנכונה הייתה צריכה להיות. אם התהליך עקבי מתחילתו ועד סופו — השמיטו שדה זה לגמרי, אל תמציאו טעות.

   אם חוסר-העקביות הוא חישוב אריתמטי מפורש ובודד שכתוב בדף (למשל שורה כמו "30 - 12" ואחריה תוצאה שלא תואמת אותו) — ציינו זאת במפורש: ציטטו את החישוב עצמו וכתבו מה הוא שווה באמת, למשל "בדקתי את החישוב `30 - 12` שכתבת — `30 - 12` שווה `18`, לא `28` שכתבת בשורה הבאה." אל תסבירו *למה* זה קרה (לא "לא שמת לב", לא "התבלבלת") — רק את העובדה החישובית. אם חוסר-העקביות אינה חישוב בודד שאפשר לאמת כך (למשל איבר שהושמט, פעולה שלא בוצעה על שני האגפים), או שאינכם בטוחים אילו מהשניים זה — המשיכו בניסוח הכללי למעלה ("...לא נובע מהשורה שלפניו" וכדומה), לעולם אל תנחשו סיווג שאינכם בטוחים בו.
```

דגשים ל-developer:
- "אל תסבירו למה זה קרה" — המשפט הזה בכוונה, לא רק דוגמה: זה האכיפה של
  product-spec.md's "לעולם לא דורשת ניחוש לגבי מצב התלמיד/ה".
- "לעולם אל תנחשו סיווג שאינכם בטוחים בו" — חוזר במפורש על העיקרון שכבר
  קיים בסוף הפרומפט ("אם כתב היד אינו קריא... אל תנחשו") אבל ממוקד כאן
  לבחירת-רגיסטר, לא רק ל-`certain`/`false` הכללי.
- הדוגמה המספרית (`30 - 12` / `18` / `28`) מכוונת בכוונה — אותו מקרה בדיוק
  מה-product-spec.md, כדי שתהיה למודל דוגמה קונקרטית ולא רק תיאור מופשט
  (אותה שיטה שהפרומפט הקיים כבר נוקט, ראו הדוגמה הקיימת ל-`processReflection`
  "ראיתי שחישבת `7 + 5` וקיבלת `12`").
- אין שינוי בשורה 43 (`processReflection`), 45 (`finalAnswer`), 47 (משפט
  ה-`certain: false`), או ב-`correctionParagraph` (שורות 33-38).

### 2 — מאגרי דימוי (`src/data/adaptiveEquations.ts`)
שורות 46-48 היום:
```ts
    isPlus
      ? `חסכת סכום כלשהו, קיבלת עוד ${a} שקל ועכשיו יש לך ${c} — כמה חסכת מלכתחילה?`
      : `היה לך סכום כלשהו, הוצאת ${a} ונשארו לך ${c} — כמה היה לך מלכתחילה?`,
```
מוחלפות בשני מאגרים חדשים (מעל `additiveEquation`, מתחת ל-`freshId`, באותו
מיקום-ברמת-מודול כמו `CARRY_ANALOGIES` ב-`adaptiveAdd100.ts`):
```ts
const ADDITIVE_PLUS_ANALOGIES = [
  (a: number, c: number) => `חסכת סכום כלשהו, קיבלת עוד ${a} שקל ועכשיו יש לך ${c} — כמה חסכת מלכתחילה?`,
  (a: number, c: number) => `היו לך כמה גולות, קיבלת עוד ${a} ועכשיו יש לך ${c} — כמה היו לך מלכתחילה?`,
  (a: number, c: number) => `היו בקופסה כמה מדבקות, הוסיפו עוד ${a} ועכשיו יש ${c} — כמה היו בהתחלה?`,
  (a: number, c: number) => `קראת כמה עמודים בספר, ואז עוד ${a} עמודים, ועכשיו קראת ${c} עמודים בסך הכל — כמה עמודים קראת בהתחלה?`,
];

const ADDITIVE_MINUS_ANALOGIES = [
  (a: number, c: number) => `היה לך סכום כלשהו, הוצאת ${a} ונשארו לך ${c} — כמה היה לך מלכתחילה?`,
  (a: number, c: number) => `היו לך כמה קלפים, נתת ${a} לחבר/ה ונשארו לך ${c} — כמה היו לך מלכתחילה?`,
  (a: number, c: number) => `היו בעציץ כמה פרחים, קטפו ${a} ונשארו ${c} — כמה היו בהתחלה?`,
  (a: number, c: number) => `היו לך כמה מדבקות באלבום, הדבקת ${a} על דף אחר ונשארו ${c} באלבום — כמה היו באלבום בהתחלה?`,
];
```
והקריאה ב-`makeQuestion` (שורה 46-48 הישנות) הופכת ל:
```ts
    isPlus
      ? pick(ADDITIVE_PLUS_ANALOGIES, rng)(a, c)
      : pick(ADDITIVE_MINUS_ANALOGIES, rng)(a, c),
```
`pick` כבר מיובא בשורה 2 של הקובץ (`import { type Rng, randInt, pick,
makeFreshId, wantsDecimal, round2 } from "./adaptiveHelpers";`) — אין צורך
בייבוא נוסף. `rng` כבר זמין בתוך `additiveEquation(rng: Rng)` (פרמטר הפונקציה
עצמה) — אין צורך להעביר אותו הלאה דרך פרמטר חדש.

## Edge Cases
- **`errorPointer` כבר מצטט ביטויים בגרשיים אחוריים היום** (`segmented()`
  בצד הלקוח כבר מטפל בזה) — הדוגמה בפרומפט (`` `30 - 12` שווה `18`, לא `28` ``)
  משתמשת באותה מוסכמה בדיוק, כך שאין צורך בשינוי בצד הלקוח כלל; הרינדור כבר
  תומך בזה.
- **המודל עדיין עלול "לטעות בסיווג"** (לבחור ברגיסטר הספציפי כשזו בעצם
  חוסר-עקביות מבני, או להפך) — זה בדיוק אותו סיכון שכבר תועד ב-
  `notebook-default-practice/architecture.md` ("errorPointer הוא היכולת הכי
  חדשה/לא-מוכחת") ולא נפתר באופן מוחלט כאן; ההנחיה החדשה רק **מכוונת** את
  ההתנהגות, היא לא ערובה. ה-fallback לניסוח הכללי נשאר תקף בכל מקרה של ספק.
- **מאגרי הדימוי בני 4 פריטים בלבד** — `pick()` עשוי (בהסתברות נמוכה) להחזיר
  את אותו דימוי פעמיים ברצף בתרגול ארוך; זה כבר המצב הקיים בכל מאגרי-דימוי
  אחרים בקוד (`CARRY_ANALOGIES` וכו׳) ולא טופל שם — אין צורך בלוגיקת
  מניעת-חזרה חדשה כאן, עקביות עם הדפוס הקיים.
- **שאלות שכבר קיימות בהיסטוריית תלמיד/ה** (נשמרו ב-`localStorage` לפני
  השינוי) — לא מושפעות: הדימוי מחושב בזמן יצירת השאלה בלבד, לא נשמר/נקרא
  מחדש, אז שינוי המאגר לא "שובר" שום דבר ישן.

## Risks / Tradeoffs
- **איכות הניסוח של `errorPointer` אינה ניתנת-לבדיקה אוטומטית** — אותה
  מגבלה שכבר תועדה במפורש ב-`notebook-default-practice/architecture.md`
  ("QA לא יכול לבדוק את איכות ההסקה הזו... רק את זרימת ה-UI סביבה עם מוק").
  **qa לפיצ'ר הזה לא יכול/ה לבדוק בפועל שהמודל אכן בוחר נכון בין שני
  הרגיסטרים** (זו תלוית-AI, לא-דטרמיניסטית) — רק את זרימת ה-UI (עיצוב
  ענברי, מיקום) עם מוק שמחזיר כל אחד מהרגיסטרים בתורו. קריטריון-הקבלה
  המדויק היחיד שניתן לבדיקה אוטומטית אמיתית בפיצ'ר הזה הוא **גיוון
  הדימויים** (דטרמיניסטי, ניתן לבדיקה ישירה: הרצת `additiveEquation` מספיק
  פעמים ובדיקה שמופיעים יותר מדימוי אחד).
- **שינוי פרומפט בלי A/B אמיתי** — כמו כל שינוי פרומפט קודם בפרויקט הזה
  (ראו "סבבי תיקון ניסוח" שתועדו ב-`notebook-default-practice`), ייתכן
  שהניסוח החדש ידרוש התאמה אחרי תצוגה מקדימה אמיתית מול Claude אמיתי — לא
  צפוי "לעבוד מושלם" מהניסיון הראשון.
- **הדימויים החדשים לא נבדקו עדיין מול `content.spec.ts` בפועל** (רק מול
  הכללים הקיימים ידנית, ב-design.md) — developer/qa צריכים להריץ את הסוויטה
  המלאה כולל `content.spec.ts` כדי לוודא שאף דימוי לא נתקל בכלל קיים (למשל
  אכילת-דבר-לא-אכיל — לא רלוונטי כאן, כל הדימויים משתמשים בגולות/מדבקות/
  פרחים/עמודים/קלפים, לא אוכל).

## Implementation Notes

נבנה בדיוק לפי התוכנית למעלה, ללא סטיות.

- **`server/src/readPage.ts`** — התוספת לסעיף 2 בפרומפט נכנסה בדיוק כפי
  שתוכנן, כפסקה חדשה תחת ההוראה הקיימת (לא סעיף 2.5 נפרד). אומת:
  `server/` כולל `package.json` נפרד עם `npm run build` משלו (`tsc -b`,
  אין סקריפט lint ייעודי) — `node_modules` לא היה מותקן, הותקן (`npm
  install` בתוך `server/`), ואז `tsc -b` רץ נקי, אפס שגיאות. נבדק גם ישירות
  (לא רק קומפילציה): המחרוזת המלאה שה-`teacherSystemPrompt()` מייצרת
  הורצה עם `expectedPrompt="x + 12 = 30"` בסקריפט חד-פעמי (לא הושאר בקוד) —
  הטקסט נקרא נכון, הגרשיים האחוריים סביב `30 - 12`/`18`/`28` לא נשברו,
  אין בעיית escaping. **לא נקראה ה-API האמיתי של Claude בשום שלב** (לפי
  ההנחיה המפורשת — יש עלות אמיתית) — האימות היחיד שאפשרי בלי קריאה אמיתית
  הוא שהניסוח שמגיע למודל קריא ונכון, לא איכות ההחלטה של המודל עצמו (ראו
  Risks למעלה, זה כבר תועד כלא-ניתן-לבדיקה אוטומטית).
- **`src/data/adaptiveEquations.ts`** — שני המאגרים (`ADDITIVE_PLUS_ANALOGIES`,
  `ADDITIVE_MINUS_ANALOGIES`) ו-`pick()` נכנסו בדיוק כמו ה-snippet בארכיטקטורה.
  אומת בפועל, לא רק בעיון: שרת פיתוח (`npm run dev`), ואז קריאה ישירה
  ל-`generateEquationsQuestion()` **האמיתי** (לא שכתוב/חיקוי) דרך
  `import()` דינמי מתוך הדפדפן (ה-URL של מודול ה-TS הממשי שה-dev server
  מגיש, לא שרת-צד שנכתב לצורך הבדיקה) — עם RNG דטרמיניסטי (LCG) כדי
  שהתוצאה תהיה ניתנת-לשחזור, 400 הרצות הניבו את **כל שמונת** התבניות
  (4 לכל כיוון), עם ערכי `${a}`/`${c}` מוצבים נכון ובלי שגיאות עברית. גם
  נבדק דרך ה-UI בפועל (עומר ← כיתה ח׳ ← משוואות) שהשאלה הראשונה שנוצרה
  (`x + 6 = 22`) תקינה חזותית — אבל מכיוון שהמחברת היא כבר מצב התרגול
  היחיד (`notebook-default-practice`), אין יותר שדה טקסט שאפשר למלא בטעות
  כדי לגרום להסבר/דימוי להופיע — הצגת ה-`errorPointer`/הדימוי בפועל על
  המסך דורשת "שלח למורה" אמיתי (קריאת Claude בתשלום), ולכן לא הופעל; האימות
  של תוכן הדימויים נעשה ברמת הנתונים (למעלה), לא ברמת מסך-אחרי-תשובה.

`npm run build && npm run lint` (אפליקציה) נקיים, `npm run build`
(`server/`) נקי. `tests/e2e/content.spec.ts` (42/42, כולל "every generated
question, across all twelve levels-as-practice topics, passes every content
rule" — מכסה את `adaptiveEquations.ts`) עבר. גרסה `1.38.0 → 1.39.0`.

# משתמשים, סילבוס ורמות — Architecture

## Overview
מודל נתונים חדש (תלמיד → כיתה → נושאים + שלוש רמות → עשר שאלות) שמחליף את
`exerciseSets.ts`, שני מסכים חדשים, ושמירת הבחירה ב-`localStorage`.

## Affected Files / Components
- **`src/data/curriculum.ts`** (חדש) — התלמידים, הכיתות, הסילבוס והשאלות. מחליף את
  `exerciseSets.ts` כמקור האמת של תוכן התרגול.
- **`src/data/exerciseSets.ts`** (נמחק) — התוכן שלו מתמזג לתוך כיתה א'.
- **`src/components/StudentPicker.tsx`** (חדש) — מסך בחירת תלמיד/ה.
- **`src/components/GradeHome.tsx`** (חדש) — מסך הכיתה: סילבוס ושלוש רמות.
- **`src/components/Home.tsx`** (נמחק) — הוחלף על ידי `GradeHome`.
- **`src/components/Practice.tsx`** (עדכון) — עובד מול `Level` במקום `ExerciseSet`.
- **`src/components/Result.tsx`** (עדכון) — אותו שינוי טיפוס.
- **`src/App.tsx`** (עדכון) — ניווט בין ארבעה מסכים במקום שלושה, וטעינת התלמיד/ה השמור/ה.
- **`src/App.css`** (עדכון) — סגנון לשני המסכים החדשים.

## Data / State Changes

```ts
interface Question {
  id: string;      // ייחודי בתוך הרמה
  topic: string;   // חייב להופיע ב-topics של הכיתה
  prompt: string;  // מה שמוצג, למשל "23 + 45" או "3x + 5 = 20"
  answer: number;
}

interface Level {
  id: "easy" | "medium" | "hard";
  title: string;        // קל / בינוני / מתקדם
  description: string;
  questions: Question[]; // בדיוק 10
}

interface Grade {
  id: string;       // "1" | "6" | "8"
  label: string;    // "כיתה א׳"
  topics: string[];
  levels: Level[];  // בדיוק 3
}

interface Student {
  id: string;
  name: string;
  gradeId: string;
}
```

**המעבר מ-`Problem` ל-`Question` הוא השינוי המהותי.** `Problem` הישן היה
`{a, b, op}` - מבנה שמסוגל לייצג רק פעולה בינארית על שני מספרים. הוא לא יכול לבטא
`3x + 5 = 20`, `25% מ-150` או `שטח מלבן 6×4`, ולכן הוא חוסם את כיתות ו' ו-ח' לגמרי.
`prompt` כמחרוזת חופשית פותר את זה: מה שמוצג הוא טקסט, והתשובה היא מספר יחיד.

התוצאה שכל תשובה היא מספר יחיד היא מכוונת ולא מקרית - היא מה שיאפשר בהמשך לזהות
תשובה שנכתבה בכתב יד. שאלות שהתשובה הטבעית להן היא שבר נוסחו כך שהתשובה תהיה מספר
(`כמה זה 3/4 מ-100?` במקום `1/2 + 1/4`).

State חדש ב-`App.tsx`: התלמיד/ה הנבחר/ת. נשמר ב-`localStorage` תחת מפתח יחיד עם
מזהה התלמיד/ה בלבד; אם המזהה השמור לא קיים יותר ברשימה, הוא מתעלם ומסך הבחירה מוצג.

## Technical Approach
`App.tsx` מנהל שני דברים נפרדים: מי התלמיד/ה (state שנשמר) ואיזה מסך פתוח (state זמני).
מסך הפתיחה נגזר מהראשון - אם אין תלמיד/ה, מוצג `StudentPicker`.

`Practice.tsx` מקבל `Level` במקום `ExerciseSet`, ומרנדר `question.prompt` במקום להרכיב
`{a} {op} {b}` בעצמו. הבדיקה משווה `Number(input) === question.answer`. הרינדור נשאר
בתוך `.problem-box` עם `direction: ltr` הקיים.

הגישה ל-`localStorage` נעטפת ב-`try/catch` - דפדפן במצב פרטי יכול לזרוק, וכישלון
בשמירת העדפה לא צריך להפיל את האפליקציה.

תוכן הלימוד נכתב לפי תוכנית הלימודים: כיתה א' - מספרים עד 20, חיבור וחיסור, מבנה
עשרוני; כיתה ו' - שברים, עשרוניים, אחוזים, יחס, שטח והיקף, ממוצע; כיתה ח' - ביטויים
אלגבריים, משוואות, חזקות ושורשים, פיתגורס, פונקציה קווית, בעיות מילוליות.

## Edge Cases
- **מזהה שמור שלא קיים** (שינוי ברשימת התלמידים) — מטופל בהתעלמות והצגת מסך הבחירה.
- **`localStorage` חסום** — נעטף ב-`try/catch`; האפליקציה עובדת, רק בלי לזכור.
- **תשובות עשרוניות** (למשל `2.5 + 1.3 = 3.8`) — ההשוואה היא על `Number`, כך
  ש-`3.80` ו-`3.8` שקולים. נמנעו שאלות שהתוצאה שלהן אינה מדויקת בייצוג בינארי.
- **תשובה שלילית** — אפשרית בכיתה ח'; שדה הקלט הוא `type="number"` ולכן מקבל מינוס.
- **סטייה בין שאלה לסילבוס** — לא נאכף בקוד אלא נבדק ב-QA, כי זו טעות תוכן ולא
  מצב ריצה; בדיקה שנכשלת עדיפה על שגיאה בזמן ריצה מול ילד.

## Risks / Tradeoffs
- **מחיקת `exerciseSets.ts` מתנגשת עם PR #2** (`feature/mistake-explanation`), שבו
  `explain.ts` מייבא ממנו `Problem` ו-`answerOf`. ההתנגשות ידועה ומכוונת: המודל הישן
  לא יכול לתמוך בכיתות ו' ו-ח'. מי שממוזג שני יצטרך להתאים את `explain.ts` לעבוד מול
  `Question`. ההסבר האוטומטי ימשיך לעבוד על שאלות חשבון פשוטות שאפשר לפרסר מ-`prompt`,
  ולשאלות מורכבות יידרש הסבר כתוב - וזה בדיוק מה שהפיצ'ר הבא ("מורה שמסבירה") נועד לתת.
- נבחר לא לאכוף בקוד את המספרים "בדיוק 3 רמות" ו"בדיוק 10 שאלות" (למשל בטיפוס טאפל),
  כי זה מקשה על הוספת תוכן בלי להוסיף ביטחון אמיתי; האכיפה היא בבדיקות.
- `localStorage` שומר רק את מזהה התלמיד/ה, לא ציונים - שמירת התקדמות היא פיצ'ר נפרד.

## Implementation Notes
נבנה כמתוכנן: `curriculum.ts` עם 3 תלמידים, 3 כיתות, 9 רמות ו-90 שאלות;
`StudentPicker` ו-`GradeHome` חדשים; `Practice`/`Result`/`App` הוסבו ל-`Level`;
`exerciseSets.ts` ו-`Home.tsx` נמחקו; הבחירה נשמרת ב-`localStorage` בתוך `try/catch`.

**סטייה אחת, שנובעת מבאג שהתגלה רק על המסך:**

הכיווניות דרשה שתי רמות טיפול ולא אחת. התכנון כיסה את הרמה הראשונה - שאלה מילולית
שלמה מוצגת RTL וביטוי טהור LTR. אבל שאלה כמו
`פתחו סוגריים: 3(x + 2). מה המספר החופשי?` היא מילולית *ומכילה* ביטוי אלגברי, ואז
אלגוריתם ה-bidi הפך את הסוגריים וסידר מחדש את האיברים: `3(x + 2)` הוצג כ-`3)2 + x(`.
הגדרת כיוון על הפסקה לא מתקנת את זה - נדרשת **בידוד** של הביטוי.

הפתרון: ביטויים אלגבריים בתוך משפט עברי מסומנים בגרשיים אחוריים בנתונים
(``כמה זה `2x + 3` כאשר...``), `promptSegments` מפצל אותם, וכל ביטוי מרונדר ב-
`.prompt-math` עם `unicode-bidi: isolate`. תשעה נוסחים סומנו כך. אומת מול הדפדפן:
`direction=ltr unicode-bidi=isolate`, והביטוי מרונדר `3(x + 2)`.

תוכן: 90 שאלות אומתו בסקריפט חד-פעמי - 3 רמות לכל כיתה, 10 שאלות לכל רמה, מזהים
ייחודיים, וכל נושא קיים בסילבוס של כיתתו. הכיסוי הקבוע הוא בדיקות ה-e2e.

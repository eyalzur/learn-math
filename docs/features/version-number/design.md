# מספר גרסה במסך הראשון — Design

## Overview
שורה אחת קטנה ומעומעמת בתחתית המסך הראשון, מתחת לכרטיסי התלמידים: המילה "גרסה"
ולצידה המספר. אין אינטראקציה, אין מצבים - זה טקסט סטטי שנמצא שם למי שמחפש אותו.

## Screens / States

מסך בחירת התלמיד/ה, אחרי התוספת:

```
┌──────────────────────────────┐
│                              │
│            מי לומד היום?     │   ← ללא שינוי
│                              │
│   ┌────────────────────┐     │
│   │ מיקה               │     │
│   │ כיתה א׳            │     │
│   └────────────────────┘     │
│   ┌────────────────────┐     │
│   │ רותם               │     │
│   │ כיתה ו׳            │     │
│   └────────────────────┘     │
│   ┌────────────────────┐     │
│   │ עומר               │     │
│   │ כיתה ח׳            │     │
│   └────────────────────┘     │
│                              │
│          גרסה 1.0.0          │   ← חדש
│                              │
└──────────────────────────────┘
```

**מיקום:** מתחת לרשימת התלמידים, ממורכז, עם רווח נדיב מעליו (כ-28px) שמפריד אותו
מהכרטיסים. הוא הדבר האחרון בעמוד.

**היררכיה חזותית - זה העיקר כאן:**

| אלמנט | גודל | צבע | משקל |
|---|---|---|---|
| `מי לומד היום?` | כותרת קיימת | `--text-h` | כותרת |
| שם התלמיד/ה | 22px | `--text-h` | 600 |
| כיתה | 15px | `--text` | רגיל |
| **גרסה** | **12px** | **`--text` בשקיפות 0.6** | **רגיל** |

מספר הגרסה הוא **הקטן והחיוור ביותר במסך** - קטן מהטקסט המשני הקיים (15px) ובצבע
המעומעם, לא בצבע הכותרות. זה מכוון: העין של ילד/ה בת 7 שסורקת את המסך מחפשת את השם
שלה, והמספר לא אמור להיכנס למסלול הסריקה הזה בכלל. מבוגר שיודע שהוא מחפש מספר
גרסה - ימצא אותו מיד, כי תחתית העמוד היא המקום המוסכם למידע כזה.

**מצבים:** אין. אין מצב טעינה, אין שגיאה, אין ריק - המספר תמיד קיים ותמיד מוצג.

**מסכים אחרים:** ללא שינוי. המספר לא מופיע במסך הנושא, הרמה, התרגול, התוצאה או
ההיסטוריה.

## Copy

| מחרוזת | הערה |
|---|---|
| `גרסה` | תווית קבועה. לא "ורסיה", לא "Version", לא "v". |
| `1.0.0` | המספר עצמו, נטען מהנתונים. |

הוחלט **לא** לוותר על המילה "גרסה" ולהציג רק `1.0.0`: מספר ערום בתחתית מסך עברי
נראה כמו שארית של באג. המילה עולה שני סנטימטרים של מקום ומסירה את הספק לגמרי.

הוחלט **לא** להוסיף תאריך, שם קומיט או "עודכן לאחרונה". הספק הוציא את זה מה-scope,
וגם עיצובית - כל תוספת כאן מגדילה אלמנט שכל מטרתו להיות קטן.

## Interaction Flow
אין. השורה אינה כפתור, אינה קישור, אין עליה hover, לחיצה או tooltip. היא נקראת
ולא נוגעים בה.

זה מכוון: כל אפשרות לחיצה במסך שילדה בת 7 סורקת היא הזמנה ללחוץ, ולחיצה על מספר
גרסה לא אמורה להוביל לשום מקום.

## Accessibility / RTL notes

**זו הנקודה שדורשת תשומת לב אמיתית בפיצ'ר הזה.**

`גרסה 1.0.0` היא מחרוזת מעורבת: מילה עברית (RTL חזק) ומספר עם נקודות (LTR). זה
בדיוק הדפוס ששבר את הפרויקט הזה שלוש פעמים - ראו `CLAUDE.md` ואת `.problem-box`
ו-`.step-math` ב-`App.css`.

**הכלל שנקבע כאן, בהתאם לכלל הפרויקט:**

1. **התווית והמספר הם שני אלמנטים נפרדים.** לא מחרוזת אחת. אסור לבנות
   `"גרסה " + version` ולתת ל-bidi של הדפדפן להסתדר.
2. **אלמנט המספר מקבל `direction: ltr` וגם `unicode-bidi: isolate`.** הגדרת כיוון
   לבדה כבר הוכחה כלא מספקת בפרויקט הזה (הבאג של `3(x + 2)`); הבידוד הוא מה
   שמונע מהמספר להשתתף בחישוב הכיווניות של השורה שמסביבו.

**האם זה הכרחי טכנית?** ברוב המקרים `1.0.0` ירונדר נכון גם בלי זה, כי ספרות
ונקודות ביניהן נחשבות רצף מספרי אחד באלגוריתם ה-bidi. אבל הפרויקט הזה כבר שילם
שלוש פעמים על ההנחה ש"זה יסתדר לבד", והבידוד עולה שתי שורות CSS. **מיישמים אותו,
גם אם התצוגה נראית תקינה בלעדיו.** אם מישהו יסיר אותו בעתיד כי "זה עובד גם ככה",
הוא יסיר רשת ביטחון, לא קוד מת.

**מה שנבדק בנוסף:**
- הכיוון של השורה עצמה (סדר "גרסה" ואז המספר) הוא RTL רגיל כמו שאר העמוד: המילה
  מימין, המספר משמאלה. זה הסדר הטבעי בעברית.
- **ניגודיות:** בשקיפות 0.6 על `--text` המספר נשאר קריא בשני המצבים (בהיר וכהה),
  אבל הוא **מתחת** ליחס הניגודיות של 4.5:1. זה מקובל כאן מפני שזה טקסט משני טהור
  שאינו נדרש לשום פעולה, ואין בעמוד מידע שקיים רק בו. אם בעתיד יתווסף לשורה הזו
  מידע שכן נדרש - יש להעלות את הניגודיות.
- **קורא מסך:** השורה נקראית כרגיל ולא מוסתרת. המילה "גרסה" נותנת לה הקשר, כך
  שהיא לא מוכרזת כרצף ספרות חסר משמעות. אין צורך ב-`aria-label` נוסף.

## עדכון (סבב 2: תיקון ה-CI)

**אין שינוי עיצובי, ואין החלטה עיצובית להכריע בה.** התיקון כולו ב-workflow
וב-סקריפט של ה-CI — הוא לא נוגע במסך, בכפתור, במחרוזת או במצב שהמשתמש/ת
רואים. שורת `גרסה 1.0.0` בתחתית המסך הראשון נשארת בדיוק כפי שתוארה למעלה.

הקהל של התיקון הוא מי שקורא **דף PR ב-GitHub**, לא מי שפותח את האפליקציה.
זה ממשק של GitHub ולא שלנו, וההחלטות היחידות שיש לנו בו הן איזה מידע לכתוב
ללוג של הבדיקה — וזו החלטה טכנית, לא עיצובית.

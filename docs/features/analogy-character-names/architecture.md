# שמות קבועים לדמויות בדימויים — Architecture

## Overview
עריכת טקסט בלבד בתוך מערכי `const` קיימים. אין state חדש, אין קומפוננטה חדשה, אין
שינוי טיפוסים. סרקתי את חמשת הקבצים שהוזכרו בספק/עיצוב (`grade1.ts`, `grade2.ts`,
`grade6.ts`, `grade8.ts`, `method.ts`) ומצאתי **33 שורות מועמדות** (כל שדה `analogy`
שמכיל מילת-מפתח של דמות אנושית), מהן **26 באמת מוחלפות** לפי כללי `design.md` והשאר
נשארות בלי שינוי מסיבה מתועדת לכל אחת — ראו הטבלה למטה. שתיים מהמועמדות הן false
positive (לא דמות בכלל) שהתגלו רק בקריאה — ראו "Edge Cases".

## Affected Files / Components
- `src/data/grade1.ts` — 13 שורות משתנות (Rule A/B), 4 נשארות (Rule C — ראו למטה).
- `src/data/grade2.ts` — 7 שורות משתנות (Rule A).
- `src/data/grade6.ts` — 4 שורות משתנות (Rule B), 2 נשארות (Rule D + false-positive).
- `src/data/grade8.ts` — 2 שורות משתנות (Rule B), 1 נשארת (false-positive).
- `src/data/method.ts` — **לא מכיל שדה `analogy` בכלל** (הקובץ בונה משפט "איך פותרים",
  לא דימוי). הוצא מה-scope בפועל — זו לא הייתה תבנית `analogy` ב-code, וההנחה בספק
  שהוא רלוונטי הייתה שגויה. אין בו שינוי.
- אין קובץ נוסף שמכיל `analogy` מחוץ לחמישה שנבדקו (`curriculum.ts` מגדיר את הטיפוס
  בלבד, לא מכיל דוגמאות).

## Data / State Changes
אין. כל שינוי הוא עדכון מחרוזת בתוך אובייקט `Question` קיים — אותו שדה `analogy:
string`, שום שינוי מבנה.

## Technical Approach
`developer` עורך כל שורה ברשימה למטה במקום (`Edit`, לא re-write של הקובץ), משאיר את
שאר השדות (`id`, `prompt`, `hints`, `steps`, `answer`) בדיוק כמו שהם. הרשימה כאן היא
הפלט הסופי של יישום כללי `design.md` על כל שורה בפועל — אין עוד שיקול דעת נדרש חוץ
מהמקרים שמסומנים "🔶 special" למטה.

## Edge Cases
- **פוליסמיה עברית ("חברה"/"מחברות")** — שתי המילים שנמצאו כ-false positive
  (`g6-ratio-m8`, `g8-equations-h5`) לא היו נראות ככה בסריקת regex גרידא; רק קריאת
  המשפט המלא חשפה שהן לא מתארות דמות. `developer` **לא** מריץ replace אוטומטי
  לפי מילת מפתח — עורך כל שורה מהרשימה הסגורה למעלה, אחת-אחת.
- **"שלך" מוסר כשמופיע** — `לאח שלך` → שם (לא `לאח שלך דניאל`), כי שם ספציפי לא
  צריך כינוי שייכות של "אח כללי". נרשם בפירוש בכל שורה שזה נוגע לה.
- **מגדר** — כל שם באחראי לוודא: דניאל/נועם → זכר, יעל → נקבה. הטבלה למעלה כבר
  התאימה לכך (למשל `g2-sub100-m1`, "לאחות", קיבלה יעל).
- **`method.ts` לא רלוונטי בפועל** — ראו "Affected Files". אין צורך לגעת בו.

## Risks / Tradeoffs
- **טווח קטן ומדויק, לא regex גורף.** יכולנו לכתוב סקריפט שמחליף "ילד"/"חבר" בכל
  מופע — נפסל בכוונה, כי בדיוק זה היה שובר `g6-ratio-m8` ו-`g8-equations-h5` (היה
  הופך "מחברות"/"חברות סלולר" לשמות ילדים). 26 עריכות ידניות/ממוקדות הן זולות מספיק
  שאין סיבה לקחת את הסיכון.
- **12 המחוללים האדפטיביים לא נכללים** (כבר הוחלט בספק) — מי שמריץ תרגול מסתגל בכל
  אחד מ-12 הנושאים ימשיך לראות דימויים גנריים שם. זה תואם את ה-Out of Scope, לא
  פספוס.
- **חזרה על אותם שלושה שמות עשרות פעמים בקובץ נתונים** היא כוונה מוצהרת (design.md),
  לא כפילות שצריך "לתקן" — אין למחולל וריאציה, זה תוכן קבוע.

## Implementation Notes

יושמה הטבלה בדיוק כפי שכתובה למעלה — 26 עריכות `Edit` ממוקדות (לא שכתוב קבצים),
אחת לכל שורת `analogy`, בארבעת הקבצים `grade1.ts` (13), `grade2.ts` (7), `grade6.ts`
(4), `grade8.ts` (2). לא נגעתי ב-`method.ts` (אין בו שדה `analogy`, כפי שהארכיטקטורה
כבר ציינה).

אימות אחרי העריכה:
- `grep` על שלושת הביטויים שאמורים להישאר בלי שינוי (`ילד מספר`, `מחברות`, `חברות
  סלולר`) הראה שהם עדיין קיימים במספר המקורי — שום שורה "לא לגעת" לא נגעה בטעות.
- `grep` על הביטויים הגנריים שהוחלפו (`לחבר"`, `לחברה"`, `לאח שלך`, `לאחות"`,
  `לילד אחד`, `שני אחים`) לא מצא אף שארית באף אחד מארבעת הקבצים.

`npm run bump:feature` הועלה ל-`1.24.0` (בראנץ' `feature/analogy-character-names`).
`npm run build` ו-`npm run lint` נקיים. לא הרצתי `npm run test:e2e` בשלב הזה — זה
תפקיד `qa`, לפי ה-pipeline.

אין סטייה מהתוכנית.

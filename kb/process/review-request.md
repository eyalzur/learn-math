המשתמש אינו מתכנת ואינו יודע לאן ללכת. **"צריך את הריוויו שלך על X" אסור.**

# ארבעת השדות (חובה בכל בקשה)
* **איפה:** קישור לחיץ.
* **איך:** נתיב מדויק — "רותם ← שברים עשרוניים ← קל ← שאלה 3 (`0.4 + 0.2`) ← הקלד `6`".
* **מה אמור לקרות:** הטקסט/התוצאה הצפויים.
* **מה לשפוט:** השאלה שהמשתמש אמור לענות עליה — "האם הניסוח מלמד, או רק מודיע".

# כללים
* בקשת ריוויו היא **תמיד** לדף תצוגה מקדימה פשוט ועצמאי (HTML אחד: `npm run build` ואז מטמיעים CSS+JS ומפרסמים) — גם כשהשינוי כבר באתר החי. לא הדרכה לנווט באפליקציה המלאה.
* ל-PR של תיעוד אין מסך: **איפה** = קישור לקובץ, **איך** = איזה סעיף, **מה לשפוט** = השאלה.
* שלוש טעויות שכבר נעשו: "ראה בטבלה למעלה" (הפניה אינה הוראה); PR שני שנזכר בלי הוראות; כלל שנכתב ל-PR שממתין לאישור (הוראה שלא מוזגה אינה בתוקף — מתקנים וממזגים).
